## 1. 需求与设计取舍

用户要求:webui 文档详情页加一个「钉子」,表示该文档会被钉在上下文里;MongoDB 文档增加 `pin` 状态;agent 部分逻辑由用户自行实现。

设计取舍:

- **独立切换接口**:钉住是即时操作,若并入既有 `PUT /api/documents/{id}`(整体更新),前端需在点钉子时把当前草稿一起提交,可能误保存未完成的编辑。因此新增 `PATCH /api/documents/{id}/pin`,只 `$set` `pinned` 字段,不触碰标题/正文/`updated_at`;
- **字段命名 `pinned`**:与 agent 侧已存在的 `pin_document` 工具和 `system_documents_prompt` 消费的字段一致,避免两套命名;
- **旧数据兼容**:响应层 `bool(document.get("pinned", False))`,旧文档缺字段时按 `false` 处理,无需迁移;
- **agent 范围收敛**:agent 的钉住工具与系统提示词消费逻辑此前已实现,本次只在 `create_document` 补 `pinned: False` 默认值,保证 webui 与 agent 两入口创建的文档模型一致。

## 2. 实现内容

### 2.1 后端(`main.py`)

- `DocumentPinRequest`(`pinned: bool`, `extra="forbid"`);
- `document_response` 增加 `"pinned": bool(document.get("pinned", False))`;

- 新增 `PATCH /api/documents/{id}/pin` → `update_document_pin`,`find_one_and_update` 仅 `$set: {"pinned": ...}`,返回更新后的完整文档。

### 2.2 API 封装(`api.js`)

- 新增 `updateDocumentPin(documentId, pinned)`:`PATCH /api/documents/{id}/pin`,请求体 `{"pinned": bool}`。

### 2.3 页面与交互(`document.html` / `document.js`)

## 3. 缺陷修复:钉住切换覆盖未保存草稿

**现象**:编辑态下未保存修改,点「钉住」后草稿被清空。

**根因**:初版 `togglePin` 用 PATCH 返回的完整文档执行 `applyDocument(...)`,`applyDocument` 会用服务端已保存正文重写 textarea,丢弃未保存草稿,且 `state.saved` 被重置为服务端内容,脏状态不再告警。

**修复**:`togglePin` 成功后只合并 `pinned` 字段到 `state.current` 与对应列表项,调用 `renderList()` 刷新标记,不触碰 textarea 与 `state.saved`;保存仍走既有 `updateDocument`(其 `$set` 不含 `pinned`),钉住状态在保存后保持不变。
