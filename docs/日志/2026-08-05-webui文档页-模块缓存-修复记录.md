# 2026-08-05 WebUI 文档页模块缓存问题修复记录

> 审查日期:2026-08-05。范围:`webui_py/main.py`(静态文件挂载)、`webui_py/static/document.js`、`webui_py/static/api.js`。
> 背景:WebUI 文档页(`document.html`)无法新建文档,点击无反应;浏览器控制台报 `Uncaught SyntaxError: The requested module './api.js' does not provide an export named 'createDocument'`。
> 本文为本次问题的根因分析与修复记录(历史快照),当前行为以源码为准。

---

## 1. 问题现象

- 打开文档页(`http://localhost:8081/document.html`),点击“新建文档”无任何反应;
- 浏览器控制台报错:

  ```
  Uncaught SyntaxError: The requested module './api.js' does not provide an export named 'createDocument' (at document.js:1:10)
  ```

- 用户确认已正确 build,但浏览器实际拿到的 `api.js` 是**旧版**(到 `submitSystemPrompt` 结束,不含 `fetchDocuments`/`createDocument` 等文档 API);实际拿到的 `document.js` 是**新版**(首行 `import { createDocument, deleteDocument, fetchDocument, fetchDocuments, updateDocument } from './api.js';`)。

## 2. 根因分析

### 2.1 直接原因:ES Module 依赖缺失,入口模块整体不执行

- `document.js` 以 `type="module"` 加载,首行从 `./api.js` 导入 5 个文档 API;
- 浏览器拿到的 `api.js` 是旧版缓存,不提供这些具名导出;
- ES Module 的具名导入在**模块链接阶段**即解析,发现缺失导出时抛 `SyntaxError`,整个 `document.js` 的模块体(含按钮事件绑定 `elements.createButton.addEventListener(...)`)都不会执行;
- 因此“新建”按钮没有绑定任何监听器 → 点击无反应。按钮无反应是加载失败的**下游症状**,不是按钮逻辑或后端路由问题。

### 2.2 深层原因:静态资源缺少重验证策略,入口与依赖版本漂移

- `webui_py/main.py` 使用裸 `app.mount("/", StaticFiles(...))`,静态响应**未设置任何 `Cache-Control`**;
- 浏览器可对 `document.js` 与 `api.js` **分别**做启发式缓存,新部署后可能出现“新入口 + 旧依赖”的混合状态(即本次事故);
- 旧缓存一旦进入浏览器,仅靠重新 build/重启容器无法清除,需硬刷新或清站点数据。

## 3. 修复过程

### 3.1 服务端:所有静态响应强制重验证

**`webui_py/main.py`**(文件末尾静态挂载处)

```python
# 修改前
static_directory = Path(__file__).parent / "static"
app.mount("/", StaticFiles(directory=static_directory, html=True), name="static")

# 修改后
static_directory = Path(__file__).parent / "static"


class RevalidatingStaticFiles(StaticFiles):
    async def get_response(self, path: str, scope: dict[str, Any]):
        response = await super().get_response(path, scope)
        response.headers["Cache-Control"] = "no-cache"
        return response


app.mount("/", RevalidatingStaticFiles(directory=static_directory, html=True), name="static")
```

- 所有静态响应(HTML/JS/CSS 等)统一带 `Cache-Control: no-cache`:
  - 允许缓存,但**每次使用前必须向源站重新验证**(`If-None-Match`/`If-Modified-Since`);
  - 部署新代码后,浏览器下次请求即拿到新内容,不再出现“入口新、依赖旧”的跨文件版本漂移;
  - `no-cache` 而非 `no-store`,304 重验证下仍可复用未变化资源,成本可接受。

### 3.2 前端:文档模块导入带版本键,立即绕开已缓存的旧 `api.js`

**`webui_py/static/document.js`**(首行)

```javascript
// 修改前
import { createDocument, deleteDocument, fetchDocument, fetchDocuments, updateDocument } from './api.js';
// 修改后
import { createDocument, deleteDocument, fetchDocument, fetchDocuments, updateDocument } from './api.js?v=documents-1';
```

- 修改导入 URL 使其**不再命中浏览器里已缓存的旧 `api.js`**,强制重新请求当前版本;
- 解决“已打开页面/已缓存旧 api.js 的浏览器”在本次修复后仍报错的问题(服务端 `no-cache` 只对未来请求生效,无法逐出旧缓存,只有改 URL 才能立即绕过);
- 版本键随文档模块 API 面变更而递增。

## 4. 验证边界(如实说明)

- 已静态核验:浏览器旧版 `api.js` 确实不含文档导出(与用户贴出的报错一致);当前源码 `api.js` 含全部 5 个导出,`document.js` 首行导入已带 `?v=documents-1`;`main.py` 自定义挂载类已就位且 `Any` 注解在文件顶部已导入;
- 后端 `py_compile` 与容器内集成测试命令在本机被取消,未能实际执行;建议容器内补:

  ```bash
  docker compose exec webui_py python -m py_compile main.py
  ```

- 建议浏览器验证:硬刷新文档页(或对 `api.js` 单独硬刷新)后,确认不再报 `SyntaxError`、“新建文档”可正常创建;再开 DevTools Network 核对静态响应头含 `Cache-Control: no-cache`。

## 5. 涉及文件

- `webui_py/main.py`(新增 `RevalidatingStaticFiles` 挂载类);
- `webui_py/static/document.js`(导入 URL 加版本键);
- 关联未改动:`webui_py/static/api.js`(文档 API 导出,本次核实已存在)。

## 6. 遗留与取舍

- 已打开且未刷新的旧页面标签仍持有旧缓存,需手动硬刷新一次;此后 `no-cache` 策略可防止再次发生;
- 版本键目前只加在 `document.js` 的依赖导入上,未做全站构建版本号统一;若后续频繁改前端,可考虑统一注入 `?v={构建版本}` 或引入构建产物指纹,属可选增强;
- 本次是“模块化改造后未配套缓存策略”的典型教训:对 `type="module"` 页面,入口与依赖必须版本一致,静态资源应始终可重验证。
