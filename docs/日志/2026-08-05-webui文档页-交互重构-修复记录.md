# 2026-08-05 WebUI 文档页交互重构与样式修复记录

> 审查日期:2026-08-05。范围:`webui_py/static/document.html`、`webui_py/static/document.js`、`webui_py/static/css/document.css`。
> 背景:文档页编辑框出现双重滚动条;交互上「预览/编辑」双态开关 + 独立重命名入口过于繁琐,需收敛为「进入编辑 → 保存/取消」的单一路径。
> 本文为本次改动的历史快照(含中间版本演进),当前行为以源码为准。

---

## 1. 问题现象与需求

- **双重滚动条**:编辑框内文字较长时,外层 `.editor-content` 与 `<textarea>` 同时出现滚动条;
- **交互冗余**:顶部「预览 / 编辑」切换 + 多个改名入口(重命名按钮、侧栏双击、标题回车)过于繁琐,用户要求收敛;
- **行为期望**:
  - 默认(打开页面 / 选中文档)为只读预览;
  - 单一「编辑」按钮进入编辑态;
  - 编辑态提供「取消 / 保存」,退出编辑态回到预览;
  - 删除按钮常驻编辑框上方;
  - 保存按钮不可用时 hover 不变绿。

## 2. 修复过程

### 2.1 编辑框双重滚动条修复(`document.css`)

参照设置页已验证模式(容器 `.setting-form` 无 `overflow`),让编辑框内容各自负责滚动:

```css
/* 修改前 */
.editor-content { position:relative; min-height:0; overflow:auto; background-color:#fafbf9; }
.editor-content textarea,.document-preview { width:100%; min-height:100%; ... }
.document-preview { white-space:pre-wrap; word-break:break-word; }

/* 修改后 */
.editor-content { position:relative; min-height:0; background-color:#fafbf9; }
.editor-content textarea,.document-preview { width:100%; height:100%; ... }
.editor-content textarea { ...; overflow:auto; ... }
.document-preview { overflow:auto; white-space:pre-wrap; word-break:break-word; }
```

- 外层 `.editor-content` 移除 `overflow:auto`,不再产生滚动条,只负责高度约束;
- 编辑态由 `<textarea>` 自身滚动(显式 `overflow:auto`);
- 预览态由 `<pre>` 自身滚动(新增 `overflow:auto` + `height:100%`);
- 两种模式各只剩一根滚动条。

### 2.2 默认预览模式(`document.js` + `document.html`)

- 初始 `state.mode` 由 `'edit'` 改为 `'preview'`;
- 新建文档(`createNewDocument`)仍进入编辑态,便于立即填写。

### 2.3 切换与保存后自动回预览(`document.js`)

- `selectDocument`:切换已有文档前先置 `state.mode = 'preview'`,任何来源都以预览打开;
- `saveCurrentDocument`:保存成功后置 `state.mode = 'preview'`,退出编辑态。

### 2.4 交互收敛:单一「编辑」按钮 + 「保存 / 取消」(`document.html` + `document.js` + `document.css`)

**HTML 结构**

```html
<!-- 顶部(编辑框上方):常驻删除按钮 -->
<header class="editor-heading">
  <div class="editor-title-wrap">...标题输入框...</div>
  <button id="deleteButton" class="delete-button" type="button" disabled>删除</button>
</header>
<!-- 页脚:取消 + 状态按钮(编辑 ↔ 保存) -->
<footer class="editor-actions">
  <span id="saveStatus" ...></span>
  <span id="characterCount" ...>0 字</span>
  <button id="cancelButton" class="cancel-button" type="button" disabled hidden>取消</button>
  <button id="editButton" class="edit-button" type="button" disabled>编辑</button>
</footer>
```

**状态机(`updateControls`)**

| 状态 | 页脚按钮 | 顶部删除 | 标题/正文 | 绿色下划线 |
|---|---|---|---|---|
| 预览 | `编辑` | 常驻可点 | 禁用 | 无 |
| 编辑 | `保存` + `取消` | 常驻可点 | 可编辑 | 有 |

- 移除顶部「预览/编辑」双态开关与 `.mode-button`/`.editor-mode` 样式;
- `editButton` 随 `state.mode` 切换文案与样式(`textContent` + `classList.toggle('save-button', ...)`),预览态为「编辑」,编辑态为「保存」;
- 点击事件:`state.mode === 'edit'` 时执行 `saveCurrentDocument()`,否则 `startEditing()`;
- 新增 `startEditing()`(进入编辑态)与 `cancelEditing()`(从 `state.saved` 恢复标题/正文并回预览);
- 新增样式 `.document-title:not(:disabled) { border-bottom:2px solid var(--green); }` 作为编辑态标题的绿色下划线标识;
- 删除按钮不再随模式隐藏,始终显示(无选中文档时禁用);
- 独立 `saveButton` 元素及对应逻辑全部移除。

### 2.5 重命名入口演进(中间版本,最终未保留)

曾实现并随后移除的改动:

- 新增底部「重命名」按钮、侧栏文档双击改名、标题框回车保存;
- 应要求全部回退,仅保留「编辑态直接修改标题 + 保存」作为唯一改名路径;
- 最终版本无独立改名入口,无 `renameButton`/`dblclick` 残留代码。

### 2.6 禁用保存按钮 hover 修复(`document.css`)

```css
.edit-button:disabled,.edit-button:disabled:hover,.cancel-button:disabled { cursor:not-allowed; opacity:.5; }
.edit-button.save-button:disabled,.edit-button.save-button:disabled:hover { border-color:var(--ink); background:var(--ink); }
```

- 禁用的「保存」按钮悬停时保持深色半透明,不再触发 `.edit-button.save-button:hover` 的绿色;
- 正常可点击的保存按钮仍保留绿色 hover 反馈。

## 5. 遗留与取舍

- 编辑态下「保存」在内容未改变或标题为空时禁用,避免无效请求;
- 未做全站按钮样式统一(如把「编辑/保存」状态按钮抽成公共组件),属可选增强;
- 删除按钮在编辑态也可用,删除前有 `confirm` 二次确认,不额外加「编辑中禁删」限制。
