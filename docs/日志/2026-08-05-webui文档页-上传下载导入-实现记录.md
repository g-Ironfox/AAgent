# 2026-08-05 WebUI 文档页上传/下载/批量导入实现记录

> 日期:2026-08-05。
> 类型:实现记录。
> 性质:历史快照(记录本次功能实现与缺陷修复过程,当前行为以源码为准)。
> 范围:`webui_py/static/document.html`、`webui_py/static/document.js`、`webui_py/static/css/document.css`。
> 说明:文档页新增 Markdown/纯文本文件上传、当前文档下载与批量导入;纯前端实现,复用既有文档 CRUD 接口,无后端改动。

## 1. 需求与设计取舍

用户要求文档页支持"单文件上传 / 单文件下载 / 批量导入",格式以 `.md` 为主,随后要求兼容 `.txt`。

设计取舍:

- **纯前端实现**:文档 CRUD 已有完整接口,上传/导入只需在浏览器读取文件内容后逐条调用 `POST /api/documents`,无需新增上传接口(后端 1MB 请求体上限、100 万字符上限已覆盖单文件场景);
- **入口合并**:单文件选择本就是多选文件控件的子集,最终只保留一个「上传」按钮(支持多选):选 1 个即上传并打开该文档,选多个即批量导入并保留当前文档,避免两个重复入口;
- **下载统一 `.md`**:当前文档无论来源(`.md`/`.txt`)统一下载为 `.md`,保持导出格式一致。

## 2. 实现内容

### 2.1 页面结构(`document.html`)

- 侧栏标题区新增「上传」按钮 `#uploadButton`,并放置隐藏多选输入 `#uploadInput`(`accept=".md,.txt,text/markdown,text/plain"`, `multiple`);
- 编辑器标题区新增「下载 .md」按钮 `#downloadButton`(无选中文档时禁用);
- `document.js` 引入 URL 加版本键 `?v=documents-2`,规避旧模块缓存。

### 2.2 上传/批量导入(`document.js`)

- `validateMarkdownFile`:扩展名白名单 `.md`/`.txt`(大小写不敏感);
- `markdownTitle`:文件名去掉扩展名作为文档标题,码点截断至 200(与后端标题上限一致),空名回退「未命名文档」;
- `importMarkdownFiles(fileList, selectImported)`:
  - 逐文件 `file.text()`(UTF-8)读取正文,码点计数超过 100 万字符时按文件报错(与后端 `MAX_DOCUMENT_CONTENT_CHARS` 一致);
  - 逐条调用 `createDocument(title, content)`;单个失败不影响其余文件,失败原因逐条汇总;
  - 成功后新文档按"最新在前"插入列表(倒序)并刷新;单选时自动打开上传的文档(置预览态),多选时保留当前文档;
  - 导入期间锁定所有操作(`state.saving`);文件输入 `change` 后重置 `value`,以便可重复选择同一文件;
  - 单选且当前文档有未保存修改时先 `confirm`。

### 2.3 下载当前文档(`document.js`)

- `downloadCurrentDocument`:以 `Blob`(`text/markdown;charset=utf-8`)+ `URL.createObjectURL` + `<a download>` 触发下载;
- 文件名取当前标题,过滤 Windows 非法字符 `<>:"/\|?*` 与控制字符、去掉结尾 `.`/空格,空名回退「未命名文档」;
- 编辑态下载使用输入框当前内容(含未保存修改),预览态使用已保存正文。

### 2.4 样式(`document.css`)

- 新增 `.library-actions` / `.document-actions` / `.file-button`(上传/下载共用按钮样式),含禁用态与 hover 反馈;
- 响应式:侧栏标题区在小屏改纵向排列,下载/删除按钮纵向堆叠,避免挤压。

## 3. 缺陷修复:上传后未编辑也提示"尚未保存"

**现象**:上传(尤其 Windows 导出的 `.txt`/`.md`,换行为 `CRLF`)完成后未做任何编辑,切换文档仍弹"当前修改尚未保存"。

**根因**:服务端保存并返回的正文含 `\r\n`;写入 `<textarea>` 后浏览器按 HTML 规范将换行规范化为 `\n`。原实现 `state.saved` 直接取自服务端返回内容,导致保存快照与输入框实际值在换行符上不一致,脏状态比较误判为"已修改"。

**修复**:`applyDocument` 先写控件、再以 `state.saved = currentInput()` 从输入框规范化后的实际值建立快照。该函数是文档打开的统一入口,同时覆盖上传后打开与从服务端重新打开两条路径。

## 6. 已知边界(详见审查报告)

- 客户端仅按字符数(100 万)校验,未按 UTF-8 字节数预检;中文内容可能超过后端 1MB 请求体上限(后端返回 400,前端会逐条报告失败);
- `file.text()` 固定按 UTF-8 解码,GBK/ANSI 编码 `.txt` 会乱码;
- 批量导入逐条串行 `POST`,复用 `api.js` 5s 超时,接近 1MB 的大文档在慢网络下可能超时。
