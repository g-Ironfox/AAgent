# 2026-08-02 webui 事件详情滚动问题修复记录

> 审查日期:2026-08-02。范围:`webui_py/static/` 前端(`index.html`/`render.js`/`app.js`/`styles.css`/`scroll-anchor.js`),为核对 ID 生成逻辑交叉阅读 `webui_py/main.py`。
> 背景:事件流页面(8081)在 event 更新后,已展开的事件详情浏览框(`pre`)滚动位置会跳回顶部,影响阅读长 JSON 内容。
> 本文为本次问题的根因分析与修复记录(历史快照),当前行为以源码为准。

---

## 1. 问题现象

- 用户展开某条事件详情(`pre` 内为格式化 JSON,`max-height: 330px` + `overflow: auto`),滚动到内容中后部;
- 前端按间隔自动刷新(`GET /api/events`),running 事件的 payload 更新(内容变化);
- 刷新后 `pre` 滚动位置回到顶部,已读内容丢失。

## 2. 根因分析

### 2.1 直接原因:运行中事件被当成"新行"重建

- 事件行 ID 由**内容指纹**派生(`main.py`:`running-{fingerprint}`、`pending-{fingerprint}-{count}`、`done-{fingerprint}-{created_at}`),指纹 = 完整事件 JSON 的 FNV 哈希;
- `render.js` 的 `renderSection` 用 `existing.get(item.id)` 复用节点,**ID 变了就视为新事件**;
- running 事件每次轮询内容都在变 → 指纹变 → ID 变 → 旧行被移除、`createEventRow` 重建新行 → 展开状态、`pre` 及其 `scrollTop` 全部随 DOM 节点销毁而丢失。

### 2.2 次要因素:恢复时机可能在布局完成前

- `updateEventRow` 原本在替换 `textContent` 后立即恢复 `details.scrollTop`;
- 即使节点被复用,`scrollTop` 赋值发生在浏览器重排/时间轴锚点恢复(`restoreAnchorState`)之前,可能被后续布局操作覆盖(该路径未在真实环境单独复现,属理论分析)。

## 3. 修复过程

### 3.1 第一轮:保留内部滚动的修复(未达预期)

在 `render.js` 中:

1. `renderSection` 增加运行中单行节点复用:当 `status === 'running' && items.length === 1 && existing.size === 1` 时,即使新 ID 与旧 ID 不同,也复用原有节点,保留展开状态与 `pre`;
2. `updateEventRow` 的滚动恢复改为 `requestAnimationFrame` 延迟执行,等待布局完成。

结果:用户实测问题仍然存在(容器内该轮改动未真正生效验证/或滚动仍被其它路径重置),随后用户明确要求采用"完全展开"兜底方案。

### 3.2 最终方案:详情完全展开,取消内部滚动

**`webui_py/static/styles.css`**

```css
/* 修改前 */
.event-details pre { max-height:330px; ...; overflow:auto; ...; }
/* 修改后 */
.event-details pre { margin:0; padding:14px; overflow:visible; color:#dce9e4; background:#1c2824; font:10px/1.6 Consolas,monospace; white-space:pre-wrap; overflow-wrap:anywhere; }
```

- 移除 `max-height: 330px` 与 `overflow: auto`;详情 JSON 按内容高度完整撑开事件行;
- 上下滚动统一由整页时间轴接管,`pre` 不再有独立滚动位置,问题从根上消失。

**`webui_py/static/render.js`**

- 删除失效的 `details.scrollTop` 捕获/恢复代码(内部已无滚动);
- 保留 3.1 的运行中节点复用逻辑:即使内容指纹变化导致 ID 改变,running 行仍复用原节点,展开/收起状态不因轮询更新而重置。

## 4. 验证

- VS Code 静态错误检查:`styles.css`、`render.js` 均无错误;
- 浏览器实测(`http://localhost:8081/`):
  - 容器已加载新资源(确认 `styles.css` 含 `overflow:visible`、无 `max-height:330px`;`render.js` 含节点复用、无 scroll 恢复代码);
  - 展开详情后 `getComputedStyle`: `overflowY: visible`、`maxHeight: none`、`scrollHeight === clientHeight`(无自身滚动条);
  - 详情 JSON 完整显示,无独立滚动区。

## 5. 遗留与取舍

- 详情完全展开后,长事件(如 tool_return 大 JSON)行高可观,整页滚动距离变长;后续如需要可考虑"懒加载/限高 + 跟随内容自适应"等折中,但需重新处理滚动保持问题;
- running 节点复用逻辑依赖"该分区恰好一行、缓存恰好一行"的保守条件,未来若 running 区出现多行(多 worker),需扩展复用策略;
- 展开状态随整页刷新重载而重置,属浏览器页面生命周期正常行为。
