# 2026-08-02 WebUI 前端 CSS 拆分审查报告

> 审查日期:2026-08-02。范围:`webui_py/static/` 前端样式(`styles.css` → `css/base.css` + `css/event-stream.css` + `css/terminal.css`),及 `index.html`/`terminal.html` 的样式引用;交叉核对 `webui_py/main.py` 静态挂载与 docker-compose 部署方式。
> 背景:原 `styles.css`(166 行)同时承载全局基础、事件流、终端三类职责,响应式规则混杂在文件末尾。本次按职责拆分为共享与页面级三个样式表。
> 本文为本次拆分的审查与修复记录(历史快照),当前行为以源码为准。

## 1. 改动概览

| 文件 | 行数 | 职责 |

## 2. 等价性核验

- **机器核验(232/232 一致)**:用括号配平解析器将原始 `styles.css`(git HEAD)与三个新文件全部规则展平为「选择器→声明体」对(`@media` 内联规则带前缀展平、组合选择器按逗号拆分、空白归一化),排序后 `Compare-Object` 无任何差异。证明拆分未丢失、未改动任何规则;
- **HTML 引用**:两个页面 `<link>` 顺序均为 `base.css` → 页面样式(必须先加载 `base.css`,CSS 变量与全局 reset 定义在其中),引用的 4 个文件均存在;
- **无残留引用**:代码侧(`webui_py/static`、`main.py`、docker-compose)已无 `/styles.css`;
- **静态检查**:5 个文件 `get_errors` 均无错误;`git diff --check` 无空白/补丁问题。

## 5. 部署与验证说明

- `main.py`:`app.mount("/", StaticFiles(directory=static, html=True))`,`/css/*.css` 直接解析到 `static/css/`,后端无需改动;
- `.dockerignore` 不排除 `static/css`,构建上下文会包含新目录;
- 生产(`docker-compose.yml`):webui_py 无 volume 挂载,需 `docker compose build webui_py` 后重启容器生效;
- 开发(`docker-compose.dev.yml`):`./webui_py:/app` 已挂载,改后直接刷新即可(该 compose 下容器 command 为 `sleep infinity`,不托管 uvicorn)。

## 6. 遗留与建议

- 项目无前端构建流程,拆分后靠手工维护加载顺序(必须 `base.css` 在前);若未来引入构建工具(如 esbuild/cssnano)可合并回单文件并自动压缩,当前不引入;
- 未继续细分(按钮/表单/状态标签等):拆分后单文件 38-89 行,规模与维护成本平衡,继续细分收益有限;
- 类名零改动,`render.js`/`app.js`/`terminal.js` 无需任何变更(类名未变,仅样式文件位置变化)。
