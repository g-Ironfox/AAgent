# 2026-08-06 WebUI 文档页钉住功能审计报告

> 日期:2026-08-06。
> 类型:审计报告。
> 性质:历史快照。
> 范围:`webui_py/main.py`、`webui_py/static/api.js`、`webui_py/static/document.html`、`webui_py/static/document.js`、`webui_py/static/css/document.css`、`agent/tools/documents.py` 的文档钉住功能。
> 说明:对本次改动做静态审查;审查中发现并修复 1 项 P2(钉住切换覆盖未保存草稿),见第 3 节;未做浏览器实测,验证边界见第 4 节。

## 1. 结论

通过。功能实现正确、与既有文档 CRUD 契约一致、无新增安全风险;审查中发现的 1 项 P2 已在同轮修复,遗留 3 项 P3 与 1 项 P4 边界(见第 3 节),不影响主流程。

## 2. 已核验

1. **契约兼容**:`DocumentRequest`(extra=forbid)未变,既有 `POST`/`PUT` 请求体不受影响;钉住走独立 `DocumentPinRequest`(`pinned: bool`,extra=forbid)与 `PATCH /api/documents/{id}/pin`;
2. **字段隔离**:`PATCH /pin` 仅 `$set` `pinned`,不触碰 `title`/`content`/`updated_at`;既有 `PUT` 的 `$set` 不含 `pinned`,两接口互不覆盖;
3. **响应兼容**:`document_response` 以 `bool(document.get("pinned", False))` 输出,旧文档缺字段时按 `false`,列表/详情/创建/更新均带 `pinned`;
4. **列表投影**:`list_documents` 投影含 `pinned: 1`,列表项直接携带钉住标记,无需逐篇拉详情;
5. **创建一致**:webui `POST` 与 agent `create_document` 均写入 `pinned: False`,两入口数据模型一致;agent 的 `pin_document` 工具与 `system_documents_prompt` 消费逻辑此前已存在,本次未改动;
6. **前端状态**:钉住按钮无文档时禁用,文案/高亮/`aria-pressed` 随 `state.current.pinned` 同步;列表对钉住文档显示标记;
7. **草稿安全(修复后)**:`togglePin` 成功后仅合并 `pinned` 到 `state.current` 与对应列表项并 `renderList()`,不重写 textarea 与 `state.saved`,编辑态未保存草稿保留;钉住状态在后续保存后保持;
8. **模块缓存**:`document.html` 入口与 `document.js` 内 `api.js` 导入版本键同步提升为 `v=documents-3`;
9. **请求体规模**:钉住请求体极小,不受文档 1MB 上限约束;`terminal_body_guard` 不拦截 `PATCH`,无影响。

## 3. 问题清单

| 级别 | 问题 | 说明与建议 |
|---|---|---|
| P2 | 钉住切换曾覆盖未保存草稿 | 初版以 PATCH 返回的完整文档 `applyDocument`,编辑态未保存修改被静默丢弃且脏状态不再告警;已改为仅合并 `pinned` 字段保留草稿(已修复,见[实现记录](../日志/2026-08-06-webui文档页-钉住-实现记录.md)第 3 节) |
| P3 | 列表不按钉住置顶 | 列表仍按 `updated_at` 降序,钉住文档不置顶;如需置顶可在 `list_documents` 排序或前端分组 |
| P3 | 钉住文档多时上下文膨胀 | agent `system_documents_prompt` 在提示词末尾附钉住文档全文,钉住数量多会撑大上下文(既有设计,agent 侧自行评估) |
| P3 | 旧文档缺 `pinned` 字段 | 响应层默认 `false` 兼容;后续按该字段查询/排序需一次性回填或建索引 |
| P4 | PATCH 返回含正文的完整文档 | 前端仅消费 `pinned`,返回体略冗余;可改 `include_content=False` |
