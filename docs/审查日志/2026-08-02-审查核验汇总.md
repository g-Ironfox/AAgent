## 3. 当前问题总表(唯一权威清单)

> 合并自:2026-08-02 当前审查清单(P0-P3)+ 2026-08-01 已知问题(P1/部署)+ 2026-08-02 webui_py 报告遗留(P1-1、P2-1..4)。问题背景与方案比较见[2026-08-01 优化报告](2026-08-01-优化报告.md)。

### P0 正确性与权限

| 问题 | 当前证据 | 建议动作 |
|------|----------|----------|
| `/` 命令无鉴权 | `task_worker.py::user_interface` 命令分支先于 `QQ_TARGET_USER_ID` 校验 | 命令分支复用授权校验,防余额/搜索配额滥用 |
| 出队后失败不重试 | LLM、工具或 QQ 发送异常后事件不重新入队 | 先引入事件 ID,再实现有限重试与失败事件记录 |

### P1 健壮性与安全

| 问题 | 当前证据 | 建议动作 |
|------|----------|----------|
| 外部 HTTP 异常处理不统一 | 余额接口对网络异常无 try/except;QQ API 裸 `raise_for_status` | 统一超时、错误分类与有限重试 |
| Worker 处理状态缺心跳 | `processing` 只有 `started_at` 无 `updated_at` | 进入处理及长任务边界刷新 `updated_at` |
| Redis 客户端反复创建 | 两个 `queue_client.py` 每次调用新建客户端 | 各进程复用模块级客户端 |
| 未使用 Key 阻塞启动 | `tool.py` 导入强读 `ZAI_API_KEY`、`BOCHA_*` | 未启用工具延迟读取配置 |
| 数据库与队列权限过大 | Redis 无密码;MongoDB 用 root 应用连接 | 接入 `REDIS_PASSWORD`,创建最小权限 MongoDB 用户 |
| 缺少 worker 所有权保护 | 单 worker 靠部署纪律保证 | 增加 Redis 锁、租约或上下文版本校验 |
| 事件无幂等与去重 | 重复投递可能导致重复回复/工具执行 | 事件唯一 ID + 处理状态 |
| FastAPI 422 破坏错误契约 | `TerminalRequest(extra="forbid")` 等触发 422 返回 `{"detail":...}` | 注册 `RequestValidationError` 处理器统一 `{"error":...}` |

### P2 精简与维护

| 问题 | 建议动作 |
|------|----------|
| `qqapi.py` 重复模板与 4 个未使用函数 | 抽 `_post`,删除 `send_private_img`/`get_group_list`/`get_group_member_info`/`get_group_msg_history` |
| qqbot `pop_from_queue` 未使用且方向错误 | 删除;如需消费统一 `BRPOP` |
| 工具 schema 与执行器分开维护 | 测试覆盖后引入工具注册表 |
| 事件与命令长 if-elif | 测试覆盖后改为分发表/命令路由表 |
| 模块级 `int(env(...))` 导入期崩溃 | `REDIS_DB`/`MONGO_PORT` 抽 `Settings`(dataclass),集中解析给默认值 |
| 时间格式不一致(`Z` vs `+00:00`) | 加 `utc_now_iso()` 统一 |
| `MAX_TERMINAL_RUNES` 命名(Go rune 遗留) | 改名 `MAX_TERMINAL_CHARS` |
| `worker_stage()` 返回 5 元组 | 改 `@dataclass` 表达阶段结果 |

### P3 WebUI

| 问题 | 建议动作 |
|------|----------|
| 无 favicon | 增加 data URI 或静态图标 |
| 搜索无 debounce | 输入增加约 150ms 防抖 |
| done 行 ID 极低概率冲突 | 暴露 MongoDB `_id` 作为历史事件稳定 ID |

### 部署风险(来自 2026-08-01 已知问题)

- MongoDB 当前使用 root 账号,应创建最小权限应用用户;
- Redis 当前无密码,公网部署必须启用认证并限制网络访问;
- `.env`、运行数据与曾泄露的密钥不得进入版本库。

## 4. 本次核验新增发现(旧文档均未记录)

| 发现 | 证据 | 建议 |
|------|------|------|
| **Redis 密码支持不一致** | `webui_py/main.py` 已读 `REDIS_PASSWORD`(`redis.from_url(password=...)`);`agent/queue_client.py` 与 `qqbot/queue_client.py` 的 `get_connection()` 均未传 password;compose 的 redis 服务也未开 `requirepass` | 若启用 Redis 认证,需同步改两处 queue_client 与 compose,否则 agent/qqbot 连不上 |
| **`created_at_desc` 单字段索引无消费者** | 全部查询已改按 `_id` 排序(`history_repository.py`、`webui_py/main.py`);`created_at_desc` 索引无查询使用 | 可删除该索引,保留 `event_type_created_at` 供终端历史过滤 |
| **`llm.py::send_messages` 打印完整响应** | `print(resp.json())` 每次 LLM 调用刷屏(含工具结果/长上下文) | 改 `logging.debug` 或删除 |
| **webui→active 事件 payload 为空** | `task_worker.py` webui 分支生成 `{"event_type":"active","payload":{}}` 并 LPUSH 普通排队 | 与"管理入口"语义一致;但该轮若触发 QQ 工具,目标 id 需工具自行提供——确认预期即可 |
