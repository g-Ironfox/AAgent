## 统一格式约定

本目录自 2026-08-05 起统一以下格式,新建或修订文档时遵守:

**文档生命周期**(循环往复):每一轮审计 = 一份**汇总**(现行活文档)+ 若干份**审计报告**(历史快照)。

1. 迭代:每次改动/审查/修复产出一份 `YYYY-MM-DD-主题.md` 记录,**先存放在 `审查日志/` 根目录**,完成后即定格为历史快照,不回写;
2. 定期合并:把审计报告中的新发现与修复证据合并进对应领域的**汇总**(见[权威清单](#权威清单));汇总只保留当前状态,历史细节一律链接回快照;
3. 归档:已合并、不再作为当前问题或已废除的报告,统一移入 `历史/`,**原封不动、不再维护**(不回写、不标注),在[索引.md](索引.md)登记;仍待处理的报告留在根目录;
4. 循环:汇总吸收新一轮审计报告后,进入下一轮迭代。

**文件名**:`YYYY-MM-DD-主题.md`,主题用半角连字符分隔,英文小写(如 `2026-08-05-webui文档页-审查报告.md`);同日多篇以主题区分。实现记录/修复记录放入 [`../日志/`](../日志/)。

**标题**:首行 `# YYYY-MM-DD 主题`(与文件名日期一致)。

**元信息**(文件开头 blockquote,字段按需出现、顺序固定,字段名与值之间用半角冒号):

> 日期:YYYY-MM-DD。
> 类型:审查报告 / 审计报告 / 汇总清单 / 长期摘要 / 修复记录 / 实现记录。
> 性质:历史快照 / 现行文档。历史快照只记录当时的观察与决策,不回写。
> 范围:<一句话说明审查/记录对象>。
> 说明:<背景、审查方式、结论性质等补充>。
> 待办:未解决问题按领域登记在[权威清单](#权威清单)对应汇总;当前行为以源码为准。

**正文结构**(审查/审计类按以下顺序,不适用的章节省略):

| 序号 | 章节 | 内容 |
|------|------|------|
| 1 | 结论 | 审查结论(通过 / 有条件 / 不通过 / 参考意见) |
| 2 | 已核验 | 已核验的正确性、契约核对(逐条编号) |
| 3 | 问题清单 | 按 P0→P4 排序,表格列:级别 / 问题 / 说明与建议 |
| 4 | 验证方式 | 静态证据、验证边界与未验证项(如实说明) |
| 5 | 涉及文件 | 本次涉及的源码与文档 |
| 6 | 建议 | 处理顺序与后续迭代方向 |
| 7 | 关联文档 | 核验汇总、接口契约与核心设计文档 |

**标点**:元信息与表格统一半角冒号/逗号;正文叙述用中文标点;代码、文件名一律半角。

**效率优先**:以高效为第一要务——每轮审查/审计直接产出问题清单,不要求在写入时先翻档案核对是否重复;重复项由下一轮**汇总**合并时统一剔除。历史快照中的问题表保留原样,不再作为当前清单;**废除/不再维护的文档统一移入 `历史/`,原封不动、不回写、不标注**。

## 维护规则(统一维护,平时请忽视)

1. 审查报告使用 `YYYY-MM-DD-主题.md` 命名,格式遵循[统一格式约定](#统一格式约定);**新报告一律存放在 `审查日志/` 根目录**,待结论被汇总吸收、定格为历史快照后再移入 `历史/`;**废除/不再维护的文档同样直接移入 `历史/`,原封不动、不再维护**;统一在[日志目录](索引.md)登记,不回写成实时说明;
2. 尚未解决的问题按领域汇总到[权威清单](#权威清单)三份问题汇总(agent / webui 前端 / webui 后端),修复后从对应汇总删除并在其第 3 节补修复证据;跨领域项归入最相关的领域汇总(如部署/安全见 agent 第 5 节);
3. 稳定且仍生效的设计结论应提炼到上级核心文档,日志只保留决策背景与专题设计;
4. 日志与核心文档冲突时,先核对源码,再修正核心文档与对应领域汇总;
5. 审计循环往复:每一轮迭代产出的审计/修复/实现记录是历史快照;定期把其中新发现与修复证据合并进对应领域的汇总(见[统一格式约定](#统一格式约定)「文档生命周期」)。
