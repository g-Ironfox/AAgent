# 2026-08-04 WebUI 事件编辑实现记录

> 本文记录 2026-08-04 WebUI 事件编辑功能的实现范围、关键决策与验证结果。它是特定时间点的实现快照；当前接口契约以 [`docs/webUI/前端API格式.md`](../webUI/前端API格式.md) 和源码为准。

## 1. 目标与范围

事件流详情新增编辑能力：

- `done`（MongoDB 历史）与 `pending`（Redis 等待队列）事件可编辑；
- `running` 事件保持只读，避免修改 Worker 已经取得的任务副本；
- 详情展开后提供“编辑”按钮，进入编辑态后切换为“保存”并显示“取消”；
- 保存、取消以及自动刷新不会主动收起当前详情；
- 编辑器宽度跟随详情网格，高度由内容撑开，不显示内部滚动条。

## 2. 后端实现

### 2.1 接口与校验

`webui_py/main.py` 新增 `PUT /api/events` 与 `UpdateEventRequest`：

- `event` 必须是 JSON 对象，并包含非空字符串 `event_type`；
- 忽略客户端传入的 `_id` 与 `created_at`，防止覆盖存储元数据；
- 请求体与编码后的事件内容上限均为 256 KB；
- 继续使用统一的 `{"error":"<中文提示>"}` 错误响应；
- 不支持修改 `running` 或其他未知状态。

### 2.2 MongoDB 历史事件

历史事件通过 `doc_id` 定位：

1. 校验并转换 MongoDB ObjectID；
2. 读取原文档的 `created_at`；
3. 使用新事件替换业务字段，同时保留原 `_id` 与 `created_at`；
4. 返回新事件指纹，供前端维持渲染身份。

### 2.3 Redis 等待事件

等待事件同时携带 `position` 与原 `fingerprint`。服务端先读取目标位置并核对内容指纹，再通过 Lua 脚本原子执行：

1. 按消费方向重新读取目标元素；
2. 比较元素原始字符串，检测读取后到写入前的队列变化；
3. 仅在一致时执行 `LSET` 替换。

目标已消费返回 `404`，队列内容变化返回 `409`，避免错误覆盖其他等待事件。

## 3. 前端实现

### 3.1 编辑状态

`render.js` 为事件详情增加 textarea 与底部操作栏：

- 点击“编辑”后以两空格缩进填入当前事件 JSON；
- 点击“取消”丢弃输入并恢复只读详情；
- 点击“保存”期间禁用保存按钮并显示“保存中”；
- 保存成功后恢复“编辑”，显示“已保存”；
- JSON 无效或接口失败时保持编辑态，提示文字与编辑框边框变红；
- 用户继续输入时立即清除旧错误状态；
- `focus({ preventScroll: true })` 防止进入编辑态时推动内部时间轴滚动。

编辑器使用 `width: 100%` 跟随详情区域，并通过 CSS `field-sizing: content` 按内容扩展高度；`overflow: hidden` 与 `resize: none` 禁止内部滚动条和手动缩放。

### 3.2 无变化不提交

`app.js` 在发起请求前解析 JSON。解析失败时不调用接口。解析成功后通过递归排序对象键生成规范化表示：

- 仅缩进、空白或对象键顺序变化视为内容未改变；
- 数组顺序仍具有语义，不做排序；
- 内容等价时直接退出编辑态并显示“内容未改动”，不调用 `PUT /api/events`，也不触发刷新。

### 3.3 展开状态保持

前端以稳定业务身份维护已展开事件集合：

- 历史事件使用 `done:{doc_id}`；
- 等待事件使用 `pending:{fingerprint}:{position}`；
- 保存后若指纹变化，将旧展开键映射到新展开键；
- 自动轮询更新 DOM 时依据集合恢复展开状态；
- 编辑中的节点跳过内容覆盖，避免轮询破坏尚未保存的输入。

## 6. 部署说明

开发 Compose 挂载 `./webui_py:/app`，刷新页面即可加载前端改动，后端自动重载取决于当前 Uvicorn 启动参数。生产 Compose 不挂载源码，需要重新构建并重启 WebUI 服务：

```powershell
docker compose build webui_py
docker compose up -d webui_py
```
