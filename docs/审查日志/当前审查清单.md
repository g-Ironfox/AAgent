# 当前审查清单

> 校对日期:2026-08-01。范围:`agent/`、`qqbot/`、`webui/`、Compose、Dockerfile 与环境变量模板。
> 本文只维护**当前仍存在**的问题。问题背景、方案比较与重构建议见[2026-08-01 优化报告](2026-08-01-优化报告.md);修复一项后直接从本清单移除,不保留历史状态。

## P0 正确性与权限

| 问题 | 当前证据 | 建议动作 |
|------|----------|----------|
| `/` 命令无鉴权 | `task_worker.py::user_interface` 在校验 `QQ_TARGET_USER_ID` 前处理命令 | 命令分支复用授权校验,避免余额泄露和搜索配额滥用 |
| `assistant.content` 可能为 `None` | `llm.py` 直接保存 `message['content']` | 写入 `response` 前使用 `message.get('content') or ""` |
| 最近历史排序不稳定 | `history_repository.py` 仍按 `created_at` 倒序 | 改按 `_id` 倒序,保证同毫秒内的插入顺序 |
| 工具参数 JSON 无容错 | response 分支直接 `json.loads(arguments)` | 解析失败时生成 `success=False` 的 `tool_return` |
| 出队后失败不重试 | LLM、工具或 QQ 发送异常后事件不会重新入队 | 先引入事件 ID,再实现有限重试与失败事件记录 |

## P1 健壮性与安全

| 问题 | 当前证据 | 建议动作 |
|------|----------|----------|
| 外部 HTTP 异常处理不统一 | 余额接口直接索引响应字段,QQ API 失败直接抛出 | 统一状态码、响应结构、超时和有限重试策略 |
| Worker 处理状态缺心跳 | `processing` 只有 `started_at`,没有 `updated_at` | 进入处理及长任务边界刷新 `updated_at` |
| Redis 客户端反复创建 | 两个 `queue_client.py` 每次调用都创建客户端 | 各进程复用模块级客户端 |
| 未使用 Key 阻塞启动 | `tool.py` 导入时强读 `ZAI_API_KEY`、`BOCHA_*` | 未启用的工具延迟读取配置 |
| 数据库与队列权限过大 | Redis 无密码,MongoDB 使用 root 应用连接 | 接入 `REDIS_PASSWORD`,创建最小权限 MongoDB 用户 |

## P2 精简与维护

| 问题 | 建议动作 |
|------|----------|
| `from tool import *` 造成隐式依赖 | 改为显式导入,尤其在 `llm.py` 显式导入 `json` |
| `qqapi.py` 有重复请求模板和未使用函数 | 抽 `_post`,删除确认未使用的四个接口 |
| requirements 含未使用的 `typer`、`rich`、`motor` | agent 保留 `pymongo/requests/redis`,qqbot 保留 `redis/websockets` |
| qqbot 的 `pop_from_queue` 未使用且方向错误 | 删除该函数;如需消费则统一使用 `BRPOP` |
| 工具 schema 与执行器分开维护 | 在测试覆盖后引入工具注册表 |
| 事件与命令使用长 `if/elif` | 在测试覆盖后改为分发表和命令路由表 |

- `.env.example` 已包含 `REDIS_SOCKET_TIMEOUT` 与 `MONGO_DATABASE`。
- 工具消息采用文本投影,不使用原生 `tool` 角色,详见[工具消息格式](../06-工具消息格式.md)。
