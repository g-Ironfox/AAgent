# 2026-08-05 WebUI 文档页上传/下载/批量导入审查报告

> 日期:2026-08-05。
> 类型:审查报告。
> 性质:历史快照。
> 范围:`webui_py/static/document.html`、`webui_py/static/document.js`、`webui_py/static/css/document.css` 的上传/下载/批量导入功能与 CRLF 脏状态修复。
> 说明:对本次纯前端改动做静态审查;未做浏览器实测,验证边界见第 4 节。

## 1. 结论

通过(有条件)。功能实现正确、与既有文档 CRUD 契约一致、无新增安全风险;遗留 3 项 P3 边界(见第 3 节),不影响主流程。

## 2. 已核验

1. **入口合并**:单文件选择为多选子集,单一「上传」按钮按文件数分流(1 个上传并打开 / 多个批量导入),逻辑自洽;
2. **契约一致**:文件名→标题(码点截断 200)、正文码点上限 100 万、逐条 `POST /api/documents`,与后端 `DocumentRequest` 限制一致;
3. **状态锁**:上传/导入期间 `state.saving=true` 并 `updateControls()`,标题/正文/按钮全部禁用,避免并发操作;
4. **部分失败语义**:单文件失败不影响其余文件,失败原因逐条汇总展示,状态区显示「部分同步」;
5. **列表顺序**:新文档 `unshift(...imported.reverse())`,保证最新在前(与 `updated_at` 降序一致);
6. **下载安全**:文件名过滤 Windows 非法字符与结尾 `.`/空格;Blob + `download` 属性不触发内联渲染;不引入 `innerHTML`,预览仍为纯文本,无 XSS/CSP 破坏;
7. **CRLF 修复**:`applyDocument` 以写入 textarea 后的规范化值建立 `state.saved`,脏状态比较不再受换行符影响;该函数为统一打开入口,新建/选择/保存/上传路径均覆盖;
8. **资源清理**:`change` 后重置输入 `value`,支持重复选择同一文件;`URL.revokeObjectURL` 及时释放。

## 3. 问题清单

| 级别 | 问题 | 说明与建议 |
|---|---|---|
| P3 | 批量导入按字符数而非 UTF-8 字节数预检 | 100 万中文字符约 3MB,超后端 1MB 请求体上限(后端返回 400,前端逐条报失败)。建议用 `new TextEncoder().encode(content).length > 1024*1024` 预检并在前端提示 |
| P3 | `file.text()` 仅按 UTF-8 解码 | GBK/ANSI 编码 `.txt` 导入会出现乱码。如需支持需加编码探测(如 BOM/GBK 探测);当前记录为已知边界 |
| P3 | 批量导入逐条串行且复用 5s 超时 | 接近 1MB 大文档慢网络可能超时失败(与既有 F8 同类)。可接受;失败项会逐条提示 |

## 4. 验证方式

- 静态证据:VS Code 对三个文件诊断零错误;元素 ID 与 `querySelector` 一一对应;无 `batchImport` 残留引用;`state.loading`/`state.saving` 覆盖上传/下载/导入路径;
- 未验证:浏览器端手工交互(单选/多选、GBK 文件、CRLF 文件、1MB 边界)未实测;`node --check` 命令行检查在会话中被取消,未取得输出。

- P3 按优先级:① 字节数预检(成本低、避免无谓的 400);② 编码边界写说明即可;③ 批量超时与 F8 一并评估;
