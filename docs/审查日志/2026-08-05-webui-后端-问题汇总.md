## 1. 领域现状

FastAPI 聚合 Worker 状态 + Redis 队列 + MongoDB 历史为三阶段快照(`worker_stage`/`pending_stage`/`history_stage`);提供事件流/终端/设置/文档四组只读与写 API;静态资源经 `app.mount("/")` 挂载;统一错误格式约定为 `{"error": "<中文提示>"}`。

## 4. 已核验正确项(无需改动)

- 契约核对:Worker 状态结构、Mongo 存储形态、指纹序列化、顺序/计数与前端假设一致;
- 文档路由顺序:精确路由先于带参路由,且全部先于 `app.mount("/")`,不会被静态文件接管;
- 同步 `def` 路由 + 阻塞 I/O:FastAPI 自动放线程池执行,无需 async;
- `limit_error()` 用 `JSONResponse` 而非 `HTTPException`:有意为之,保住 `{"error":...}` 契约;
- `GET /api/documents` 列表只投影 `title/created_at/updated_at`,轻量;
- `pending_stage` 中 `llen`/`lrange` 之间的小竞态是原有设计,`lrange` 越界安全,不改。

## 5. 部署与安全(webui 相关)

- webui_py 无 volume 挂载,改动需 `docker compose build webui_py`;dev compose 挂载源码直接生效;
- webui 已支持 `REDIS_PASSWORD`,但 agent/qqbot 未同步(见 [agent 问题汇总](2026-08-05-agent-问题汇总.md) A18);
- 静态资源已配 `Cache-Control: no-cache`,配合前端模块版本键避免旧缓存。
