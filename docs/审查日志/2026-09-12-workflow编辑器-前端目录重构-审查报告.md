## 1. 结论

有条件通过。重构将前端拆为「domain(3) + editor(1) + inspector(3)」后,节点/连接/边界端口契约与后端逐项对齐,旧三模块的行为等价性逐操作核验通过,并顺带修复 3 处旧实现缺陷(见 2.8);遗留 2 项 P1(均为旧行为延续、现已集中在 domain 层可单点修复)、4 项 P2、1 项 P3 与 1 项 P4,不影响当前主流程,但 P1 会在执行期被 `validate_workflow` 拒绝,建议优先处理。

## 2. 已核验

1. **目录与职责**:`workflow/domain/node-contract.js`(节点类型/默认值/端口契约)、`connection-rules.js`(连接校验与失效清理)、`serialization.js`(状态/快照/导入归一化);`workflow/editor.js`(画布渲染、连线、拖拽、平移、瞬态选择状态);`workflow/inspector/`(公共调度、结构编辑、外部集成);入口 `workflow.js` 仅保留页面组装与导入导出流程;全目录检索确认旧 `model.js`/`view.js`/`connections.js` 无残余引用;
2. **连接对象契约**:`{id, fromId, fromPortId, toId, toPortId, type}`、5 种类型枚举、单后继/单源语义(`multiple` 标记 → 拖拽覆盖规则)与 `workflow_validator.py` 的唯一性约束一致;控制流自环与环均不额外拒绝,与后端一致;
3. **端口契约矩阵**(`portsForNode()` ↔ `data_ports_for_node`/`control_ports_for_node`)逐节点核对一致:

| 节点 | 控制输入 | 控制输出 | 数据输入 | 数据输出 |
| --- | --- | --- | --- | --- |
| input | - | control-out | - | workflow:<name> |
| output | control-in | - | workflow:<name> | - |
| router | control-in | branches[].id | content-in | - |
| construct_message | control-in | control-out | content-in (content) | message-out (message) |
| construct_content | control-in | control-out | append-in-N (content) | content-out (content) |
| construct_list | control-in | control-out | {item_type}-in-N | list-out (list-{item_type}) |
| foreach | control-in, loop-in | control-out, loop-out | list-in (list-{item_type}) | item-out (item_type) |
| llm | control-in | control-out | message-in-N (message) | output、reasoning(think)、tool_calls(tool_calls) |
| tool | control-in | control-out | parameters (content) | output (content) |
| tool_call | control-in | control-out | tool_call (content) | tool_call_id、result (content) |
| workflow | control-in | control-out | workflow:<name> | workflow:<name> |

4. **边界契约**:`input_ports`/`output_ports` 存 `{name,type}`;边界节点 `workflowPorts` 存 `{id,name,type}` 且 `id = workflow:<name>`;与 `boundary_ports()`、webui `synchronize_metadata_ports()` 同源;自动补建 Output 节点会带 `workflowPorts`(见 2.8③);
5. **可调用 Workflow 引用链**:`workflow_nodes[{name,...}]` → 节点 `workflow_name` → 节点库 `data-add-workflow-node=name`;webui 重命名传播的也是 `workflow_nodes.name`/`nodes.workflow_name`;编辑器导出不再包含 `workflow_id`,导入侧两处仍兼容读取(`serialization.js` L64/L130),`agent/test_workflow_node.py` 的 `assertNotIn("workflow_id", ...)` 与之一致;
6. **导出/上传通路**:webui 上传先 `updateWorkflowMetadata` 再 PUT,PUT 载荷剥离 `workflow_nodes`、节点级剥离 `workflow_id`,字段与 `WorkflowRequest(extra="forbid")` 完全吻合;`resolveWorkflowReferences` 对 `name`/`workflow_name`/`workflow_id` 三种引用形态均兼容;
7. **行为等价性(旧 `view.js`/`connections.js` 对比)**:分支增删改、内容项增删改、列表类型/数量、foreach 类型、LLM 输入增删、Think/ToolCalls、Tool 选择、模型选择逐操作比对结果等价;旧实现中散落的 `state.connections.filter(...)` 全部收敛为 `reconcileConnections(state)`,按完整端口契约重新校验;
8. **旧缺陷修复(本次顺带消除)**:
   - ① 旧实现修改 `construct_list` 的 `initial_value_count` 时会误删指向 `control-in` 的控制连接(增/减均触发);新实现按契约联动,控制连接保留;
   - ② 旧导入过滤器在「控制流源为 output 节点」时访问不存在的 `branches` 并抛出,导致整份文档加载失败;新实现按端口契约正常过滤;
   - ③ 旧实现在导入缺少 Output 时补建的节点不带 `workflowPorts`,保存/执行会被拒;新实现带上当前输出契约;
9. **编辑手势**:`editor.js` 与旧 `connections.js` 逐段比对等价(重连改端点、取消回滚、兼容端口标记、画布平移、节点拖拽、拖拽预览路径);
10. **入口迁移完整性**:`createInspector` 在首次渲染前注册 renderer;resize 绑定、文件/文本/剪贴板导入、元数据对话框保存、节点库点击均指向新模块;`workflow_edit.html` 脚本版本 `v6 → v7`;
11. **静态诊断**:9 个改动文件均无 VS Code 诊断;`git diff --check` 通过;全项目其余告警为 `webui_py` Python 依赖未解析(环境未安装),与本改动无关;
12. **规范一致性**:`docs/11-Workflow设计规范.md` §4.5「接口契约」的 label/type 与 `data-port-label`/`data-port-type` 同源(同一 `portsForNode()` 结果),按方向分组、空态文本保留;§6.3 端口查找仅用 `[data-port-id]`;§6 要求「节点类型差异集中在 nodePorts」现由 `portsForNode()` 单点承接(模块边界描述本身待同步,见问题清单)。

## 3. 问题清单

| 级别 | 问题 | 说明与建议 |
| --- | --- | --- |
| P1 | 边界端口 id/name 不一致(>80 字符名) | `boundaryPorts()` 用未截断名拼 `id`、`name` 截断到 80;名字超长时 `id != workflow:<name>`,`_validate_workflow_ports` 会在执行期(`task_worker.py` L278/L410)报错。旧实现同病,现集中在 domain 层。建议先 trim+slice 得到 name,再拼 id,并过滤空名 |
| P1 | 导入归一化可产出重复/空 `append_items` | `normalizeNode` 对 port 项不去重,且全非法项时 flatMap 产物为空;违反 `_validate_construct_content`(port_id 唯一、`dataInputPorts` 等集、列表非空)。建议把 `structure.js` 的 `syncPorts` 规则提炼为 domain 纯函数,导入与 Inspector 共用;flatMap 后为空则回退默认项 |
| P2 | 前端比后端严格(中间节点数据类型) | Python `filter_connections` 只查端口存在性(如 `content` → `llm.message-in-0` 后端接受),编辑器按端口类型丢弃 → 「外部文件 → 编辑器 → 导出」会静默丢连接。建议二选一:文档明示编辑器语义更严;或把类型规则抽为共享表对齐 |
| P2 | 元数据空名与空白名未拦截 | `workflow.js` 提交校验只查重,单侧单个空名可过;后端 `min_length=1` 会拒。另服务端保存时 `strip()` 名称,而导入载荷保留原始空格,带前后空格的端口名会导致 PUT 相等性校验失败(提示"请刷新后重试")。建议前端提交前补判空并在归一化统一 trim |
| P2 | `initial_value_count` 瞬态字符串与 0 显示为空 | 通用 `[data-field]` 绑定原样写入字符串,依赖后续 `change` 事件才转 int;且 `node[field] || ''` 使 `0` 在输入框显示为空。建议字段绑定按输入类型做一次强制转换 |
| P2 | 文档漂移:设计规范 §6「前端模块边界」 | `docs/11-Workflow设计规范.md` §6 仍描述 `model.js`/`view.js`/`connections.js` 三模块职责,本次重构已改为 domain(3)/editor(1)/inspector(3)。建议同步 §6,并把「集中在 nodePorts(node)」改述为 `portsForNode()` |
| P3 | 导入静默过滤无提示 | 失效连接与无效节点被静默丢弃(如 workflow 节点缺 `workflow_name` 直接移除),排障困难。建议导入后回显「已忽略 N 条失效连接/节点」 |
| P4 | 多份记录文档仍引用旧路径 | `docs/14`、`docs/15`、`docs/Workflow动态端口改动记录.md`、`docs/Workflow调用节点改动记录.md`、`docs/Workflow重置行为改动记录.md` 仍引用 `webui_py/static/workflow/*`(编辑器迁出后已不存在);属既有漂移,可在下一轮汇总时统一订正 |
