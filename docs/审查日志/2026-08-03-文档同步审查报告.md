## 1. 代码侧重写要点(审查依据)

本次重写集中在 `agent/task_worker.py`、`agent/prompt/system.txt`、`agent/tool.py`。核实到的关键事实:

| 事实 | 证据(源码位置) |
|------|----------------|
| `handle_task()` 用 `handle_map` 按 `event_type` 查表分发,取代 `if/elif` 链 | `task_worker.py` 内 `handle_map`、`handler = handle_map.get(e['event_type'])` |
| 新增 `setting` 事件:非空 `system_prompt` 覆盖 `prompt/system.txt` | `task_worker.py` setting handler 写文件 |
| 系统提示每次 `active` 从 `prompt/system.txt` 读取,并替换 `{{TARGET_USER_ID}}`/`{{BOT_ID}}` | `task_worker.py` active 分支读文件 + `.replace()` |
| terminal 事件投影为 `<Command>{message}</Command>` | `task_worker.py` active 分支消息组装 |
| QQ 触发的 `active` 仍携带 `user_id`/`group_id` 来源元数据 | `task_worker.py` `user_interface()` 构造 active |
| 注册工具共 5 个:余额×2、搜索×1、QQ 消息×2 | `tool.py` `tools` 列表 |
| `system.txt` 中 Terminal 格式为 `<Command>内容</Command>` | `agent/prompt/system.txt` |

重写本身逻辑正确:`handle_map` 分发与旧 if/elif 行为一致;`setting` 只在消费时生效,不触发 LLM、不投影为消息;多 `tool_calls` 经 `events[::-1]` + RPUSH 保证 BRPOP 消费顺序正确(此前遗留的执行顺序反转已由该写法解决)。

### 3.1 潜意识搜索边界纠正(用户确认后落笔)

用户明确:单纯用关键词/实体/消息类型规则匹配,能直接覆盖的隐含信息需求有限;而让通用主模型完整判断"缺什么、搜什么、是否继续搜"再执行,本质就是提前一轮 ReAct,重复主 Agent 能力与成本。文档据此修正为:

- **保留方向**:参考 Pre-Tool/工具组预选,在正式思考前增加一次职责单一的搜索阶段;
- 该阶段可用特化小模型加速,只负责生成查询、初筛候选,不制定计划、不执行搜索之外的工具、不开展无限行动循环;
- 结果只是带来源的候选材料,由主 Agent 在同一条线性时间线上评估;失败时直接降级进入主 Agent;
- 待办第 20 条:设计前置搜索的结构化接口、触发条件、查询/延迟预算、候选材料格式与失败降级,并评估特化小模型收益。
