## 2. 已核验的正确性

1. **工具注册链路完整**:`task_worker.py` 顶部 `import tools.qq` + `from tools.documents import list_documents` 触发两个模块内的 `@tool` 注册;`llm.py` 引用 `tools.tool` 的 `tools` 列表。三处模块在 `chat_with_deepseek` 调用前均已加载,最终工具列表 = 余额/搜索(3) + QQ 发送(2) + 文档(6) 共 11 个,无重名(重名会触发 `ValueError` 报错);
2. **导入清理干净**:全仓 grep 确认无残留的 `from tool import ...`、`from qqapi import ...` 旧式引用;`qqbot/`、`webui_py/` 未引用被移动的模块,移动安全;
3. **部署配置自洽**:`agent/Dockerfile` 为 `COPY . .`,`tools/` 目录随镜像打包;容器 `command` 为 `python task_worker.py`,工作目录含 `tools/` 包;`.env` 含 `MONGO_HOST=mongodb`、`MONGO_USER`/`MONGO_PASS`,agent 经 `env_file` 可连 MongoDB;`documents.py` 默认 `MONGO_DATABASE=agent`、`MONGO_DOCUMENT_COLLECTION=documents`,与 `webui_py` 一致,LLM 工具与 WebUI 共享同一 `documents` 集合,存储契约统一;
4. **system prompt 占位符正确**:`system.txt` 新增 `{{DOCUMENTS_INDEX}}`,`active()` 运行时以 `list_documents()` 替换;WebUI 缓存/展示的是含占位符的原始 prompt(`apply_system_prompt` 原样写回),保存后再渲染仍生效,无占位符丢失风险;
5. **`documents.py` 与 WebUI 职责隔离**:按注释意图为解耦重写 CRUD,未复用 FastAPI 层;长度上限(标题 200/正文 1,000,000 字符)与 WebUI 契约一致;`append`/`rewrite` 在超限时抛 `ValueError`,由 `tool` 事件处理器捕获返回 `success=False`,不会崩溃;
6. **`utils.env()` 语义正确**:`os.getenv(name) or fallback`,空字符串回退,符合预期;
7. **消息入口逻辑等价(除命令分支)**:新内联 `qq()` 的"目标用户 + (私聊或艾特)"判定、空消息跳过、`publish_to_queue` 触发 `active`,与旧 `user_interface` 一致;
8. **队列语义无回归**:`publish_to_queue`(LPUSH)+`brpop`(FIFO)、`insert_to_queue`(RPUSH)+`brpop`(LIFO) 未改动;`active` 中 `insert(e2,e)` 先处理 response 再回 active、`response` 中 `events[::-1]` 保持工具顺序,均与既有行为一致。

## 3. 问题清单

| 级别 | 问题 | 说明与建议 |
|------|------|-----------|
| **P1(待决策)** | **斜杠命令功能回归 + `command.py` 死代码** | 旧 `user_interface` 对以 `/` 开头的消息直接执行 `dsB/kmB/B/search` 并回复,不经过 LLM;重构后 `qq()` 将所有非空消息(含命令)一律投给 LLM。新文件 `command.py`(函数名误拼为 `commad`)从未被任何模块 import。**二选一**:① 在 `qq()` 中接入 `commad()` 恢复直答(推荐,省 token、行为确定);② 若有意让 LLM 用工具处理命令,则删除 `command.py` 及其中无效引用 |
| P2 | `documents.py` 用布尔值当 `return_document` 枚举 | `append_to_document`/`rewrite_document` 传 `return_document=return_final`;pymongo 的 `ReturnDocument` 是 IntEnum(`BEFORE=False`/`AFTER=True`),布尔恰好等效可用,但语义隐晦、依赖巧合。建议显式 `ReturnDocument.AFTER/BEFORE` 并简化返回逻辑 |
| P2 | `rename_document` 返回的是**旧标题** | `find_one_and_update` 默认返回更新前文档,`res['title']` 为重命名前的值,会误导 LLM 确认结果;建议 `return_document=ReturnDocument.AFTER` 或单独回读 |
| P2 | `append`/`rewrite` 在 `return_final=False` 时返回更新前文档的 `str()` repr | `str(dict)` 输出含 `ObjectId('...')` 的 Python 字典字面量,格式混乱且是旧内容;建议未要求返回时返回简短确认(如"已追加/已重写") |
| P3 | `query_document_by_id`/`document_wrapper` 缺 None 检查 | 文档不存在时 `i['title']` 抛 `TypeError`,被上游 `tool` 处理器捕获成 `Error: ...`;建议显式返回"文档不存在: {id}" |
| P3 | `query_document_by_name` 未命中返回空串 | LLM 收到空结果,建议返回"未找到文档" |
| P3 | `list_documents()` 每轮 `active` 全量扫描 | 无投影/排序,每次消息都 `find()` 全部文档拼进 system prompt;文档量大时建议 `projection={title,_id}` + 按 `updated_at` 排序,或加缓存 |
| P3 | `MAX_DOCUMENT_BODY_BYTES` 定义了未使用 | 死常量,建议删除或用于请求体校验 |
| P3 | `document_wrapper` 与 `query_document_by_id` 逻辑重复 | 可提取共用格式化函数 |
| P3 | `import tools.qq` 副作用式注册 | 工具注册依赖 `task_worker` 的导入顺序;`llm.py` 只 import `tools.tool`,若未来其他入口直接 import `llm`,工具列表将缺 QQ/文档工具。建议在 `tools/` 下提供显式注册入口(如 `tools/__init__.py` 统一 import) |
| P3 | `agent/tools/` 无 `__init__.py` | 依赖 Python3 隐式命名空间包,当前可跑;显式添加更稳、避免工具链误判 |
| P3 | `system.txt` 末尾无换行 | 拼接占位符后可能粘连,建议补换行(纯格式) |
