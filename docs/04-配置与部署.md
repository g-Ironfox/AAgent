# 04 配置与部署

本页用于完成本地 Docker Compose 部署。环境变量模板见根目录 `.env.example`。

> **部署前只需确认三件事**
>
> 1. 已安装 Docker Desktop 与 Docker Compose;
> 2. `.env` 中所有 `replace-me` 均已替换;
> 3. `agent` 始终保持单实例。

## 1. 快速启动

在项目根目录执行:

```powershell
Copy-Item .env.example .env
# 编辑 .env,填入 API Key 和 MongoDB 密码
docker compose up --build -d
docker compose logs -f agent
```

启动后可访问 WebUI: `http://localhost:8081`。

常用运维命令:

```powershell
docker compose ps                    # 查看服务状态
docker compose logs -f agent     # 跟踪 agent 日志
docker compose down                  # 停止服务,保留 data/ 中的数据
```

### 1.1 开发调试模式(仅本地开发使用)

正式配置(`docker-compose.yml`)不挂载源码、不暴露 Redis/Mongo 端口,适合发布运行。开发调试时叠加 `docker-compose.dev.yml`:

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
```

开发模式与正式模式的区别:

| 项 | 正式配置 | 开发模式叠加配置 |
|----|----------|------------------|
| `agent` / `qqbot` 源码 | 打包进镜像,改代码需重新构建 | 挂载宿主机 `./agent`、`./qqbot`,改动即时生效 |
| `agent` / `qqbot` 启动 | 直接运行入口脚本 | `sleep infinity` 挂起,手动 `docker compose exec` 启动 |
| 依赖启动条件 | 等待 Redis/Mongo `service_healthy` | `service_started`,容器创建即继续,启动更快 |
| `redis` | 仅容器内部访问 | 暴露 `6379` 到宿主机 |
| `mongodb` | 仅容器内部访问 | 暴露 `27015:27017` 到宿主机 |

开发模式下手动启动 worker:

```powershell
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec agent python task_worker.py
docker compose -f docker-compose.yml -f docker-compose.dev.yml exec qqbot python listener.py
```

> 不要用 `-f` 叠加配置的方式部署到生产;发布时使用根目录的 `docker-compose.yml` 即可。

## 2. 必须遵守的部署约束

> **`agent` 必须保持单实例。** 不要使用 `docker compose up --scale agent=N`,也不要启动第二个 worker 消费同一队列。多个 worker 会并发读取同一权威历史,造成 LLM 上下文分叉。

- 五个服务均接入桥接网络 `rainbow_net`;
- 容器之间通过服务名 `redis`、`mongodb` 访问依赖;
- 运行时数据保存在 `data/`,执行 `docker compose down` 不会删除;
- 不要将 `.env` 或 `data/` 提交到版本库。

## 3. 环境变量

### 3.1 启动必填

以下变量在当前代码中没有完整默认值。即使某项功能尚未接入主工具链,相关模块也可能在启动导入时读取变量,因此应全部填写。

| 变量 | 用途 |
|------|------|
| `DEEPSEEK_BASE_URL` / `DEEPSEEK_API_KEY` | DeepSeek API 地址与密钥 |
| `KIMI_BASE_URL` / `KIMI_API_KEY` | Kimi API 地址与密钥 |
| `ZAI_API_KEY` | 智谱/GLM 密钥;当前主线未使用,但启动时仍会读取 |
| `TAVILY_API_KEYS` | Tavily 搜索密钥;多个密钥用逗号分隔 |
| `BOCHA_BASE_URL` / `BOCHA_API_KEY` | 博查 API 地址与密钥;当前未注册到 LLM 工具链 |
| `QQ_API_BASE_URL` / `QQ_API_TOKEN` | QQ HTTP API 地址与 Token,用于发送消息 |
| `QQ_WS_URI` / `QQ_WS_TOKEN` | QQ WebSocket 地址与 Token,用于接收事件 |
| `QQ_TARGET_USER_ID` | 允许触发 LLM 的用户 QQ 号 |
| `QQ_BOT_ID` | 机器人自身 QQ 号 |
| `MONGO_USER` / `MONGO_PASS` | MongoDB 初始化及应用连接凭据 |

### 3.2 有默认值

通常可沿用 `.env.example` 中的值:

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `DEEPSEEK_MODEL` | `deepseek-v4-pro` | DeepSeek 模型名 |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` | Redis 容器地址 |
| `REDIS_SOCKET_TIMEOUT` | `30` | Redis socket 超时秒数 |
| `AGENT_QUEUE_NAME` | `agent_tasks` | 任务队列名 |
| `AGENT_WORKER_STATUS_KEY` | `aagent:worker:status` | worker 状态 Key |
| `MONGO_HOST` / `MONGO_PORT` | `mongodb` / `27017` | MongoDB 容器地址 |
| `MONGO_DATABASE` | `agent` | 数据库名 |
| `MONGO_HISTORY_COLLECTION` | `event_history` | 历史事件集合名 |

表中是代码与模板的默认值,运行时以 `.env` 的实际配置为准。例如设置 `MONGO_HISTORY_COLLECTION=history` 后,应用会使用 `history` 集合而不是默认的 `event_history`。

## 4. 端口与服务

| 服务 | 宿主机端口 | 容器端口 | 说明 |
|------|------------|----------|------|
| `webui_py` | `8081` | `8081` | 监控页面与 `/api/*` 接口 |
| `redis` | 不暴露 | `6379` | 仅供 Compose 内部服务访问 |
| `mongodb` | 不暴露 | `27017` | 仅供 Compose 内部服务访问 |

`agent` 与 `qqbot` 不直接暴露端口。QQ HTTP/WebSocket 服务通常通过 `host.docker.internal` 访问宿主机。

## 5. 安全检查

部署前逐项确认:

- [ ] `.env` 已被 `.gitignore` 排除;
- [ ] 所有示例密钥和弱密码均已替换;
- [ ] 曾出现在源码或 Git 历史中的密钥已经吊销并重新生成;
- [ ] 公网部署时,Redis 已启用认证并限制网络访问;
- [ ] MongoDB 已改用最小权限应用账号,而非长期使用 root 账号;
- [ ] 只有一个 `agent` 实例消费当前队列。

## 6. 目录参考

日常部署只需关注以下路径:

```text
AAgent/
├── .env.example         # 环境变量模板
├── .env                 # 本地密钥与配置,禁止提交
├── docker-compose.yml   # 服务编排
├── agent/               # Agent worker、LLM 与工具代码
├── qqbot/               # QQ 事件监听器
├── webui/               # 监控服务与静态页面
├── docs/                # 项目文档
└── data/                # MongoDB / Redis 运行时数据,禁止提交
```

模块级文件职责见[模块详解](03-模块详解.md),服务关系见[系统架构](01-系统架构.md)。
