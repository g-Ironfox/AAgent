# Workflow 配色规范

本文定义 Workflow 编辑器的颜色语义、节点职责色、数据类型色和交互状态色。目标是在保持工作台界面克制、可扫描的前提下，提高节点和连线的辨识度，并避免同一种颜色同时表达多种含义。

## 1. 设计原则

Workflow 配色分为三个相互独立的层次：

1. 节点职责色回答“这个节点负责什么”。
2. 数据类型色回答“这个端口或连接传递什么”。
3. 交互状态色回答“用户当前正在操作什么，系统处于什么状态”。

不同层次不能因为视觉接近而共享语义。例如，LLM 节点可以使用靛蓝色，但它的 `content` 输出端口仍使用数据类型规定的钴蓝色。选中 LLM 节点时，选中轮廓使用统一的交互色，而不是继续加深节点职责色。

颜色只作为辅助编码。节点必须同时显示符号和类型名称，端口必须显示标签，连接类型必须同时通过线型区分，不能要求用户仅凭颜色理解 Workflow。

## 2. 中性色基础

编辑器主体保持低饱和浅色背景，为节点和连接提供足够的视觉空间。

| 变量 | 色值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F4F5F1` | 页面和编辑器背景 |
| `--canvas-grid` | `#DFE4DF` | 画布网格线 |
| `--surface` | `#FFFFFF` | 节点、面板和表单表面 |
| `--ink` | `#17201D` | 主要文字和强轮廓 |
| `--muted` | `#68736E` | 次要文字和端口标签 |
| `--line` | `#D8DDD9` | 普通边框和分隔线 |

中性色不表示业务类型。不得使用画布灰、边框灰或次要文字灰表示特定节点或数据类型。

## 3. 节点职责色

节点职责色用于节点顶部色条、节点符号背景和节点库左侧标记。节点主体保持白色，不能大面积填充职责色，以免节点较多时画布失去信息层级。

| 节点类型 | 变量 | 色值 | 语义 |
| --- | --- | --- | --- |
| `input` | `--node-input` | `#29332F` | 流程入口与基础输入 |
| `router` | `--node-router` | `#A65F00` | 判断、路由和控制分支 |
| `llm` | `--node-llm` | `#4658A8` | 模型推理与智能处理 |
| `construct_message` | `--node-message` | `#BB405B` | 消息封装和角色构造 |
| `construct_content` | `--node-content` | `#16768A` | 文本内容加工 |
| `construct_list` | `--node-list` | `#7651A1` | 集合与结构转换 |
| `tool` | `--node-tool` | `#1B774F` | 外部能力调用和执行 |

节点职责色的使用范围：

- 节点顶部使用 `4px` 色条。
- 节点符号使用职责色背景和白色前景。
- 节点库项目使用同色左侧标记。
- 检查器可以使用小面积职责色标识当前节点类型。

节点职责色不得用于端口、连接线、成功提示或焦点轮廓。

## 4. 数据类型色

数据类型色用于端口、连接线、连接预览、画布图例和检查器中的端口合同。相同数据类型在所有位置必须使用相同颜色。

| 数据类型 | 变量 | 色值 | 连接线型 |
| --- | --- | --- | --- |
| `control` | `--type-control` | `#16845B` | 实线 |
| `content` | `--type-content` | `#2F6FBB` | `5 5` 短虚线 |
| `message` | `--type-message` | `#D05A24` | `2 4` 点状虚线 |
| `list-content` | `--type-list-content` | `#D12F72` | `8 3` 长虚线 |
| `list-message` | `--type-list-message` | `#7251B5` | `8 3 2 3` 复合虚线 |

列表类型不能只通过紫色或洋红色表示。`list-content` 和 `list-message` 必须使用不同线型，使连接在灰度显示和常见色觉差异下仍可区分。

端口默认直径为 `12px`，保留白色内边框和深色外轮廓。端口颜色只填充圆点内部，避免小尺寸高饱和色块干扰端口标签。

## 5. 交互与状态色

交互状态使用独立颜色，不复用节点职责色或数据类型色。

| 状态 | 变量 | 色值 | 建议表现 |
| --- | --- | --- | --- |
| 当前选择或键盘焦点 | `--interaction` | `#17201D` | `2px` 深色外框，保留间距 |
| 成功或已保存 | `--status-success` | `#18734C` | 文字、图标或小面积背景 |
| 警告或未保存 | `--status-warning` | `#B77900` | 徽标和提示边框 |
| 错误 | `--status-error` | `#B83A35` | 错误文字、边框和图标 |
| 禁用 | `--disabled` | `#98A19C` | 降低对比度并保留文字说明 |

交互规则：

- 选中节点统一使用 `--interaction`，不能按节点类型改变选中轮廓。
- 兼容端口使用端口自身的数据类型色生成外圈，同时通过尺寸变化提示可连接状态。
- 连接拖拽预览使用目标数据类型色，建议透明度为 `0.8`。
- 错误不能只将内容改成红色，还必须显示错误文字或图标。
- 成功状态不能复用 `control` 的绿色变量，即使两者色相接近也必须保持变量和语义独立。

## 6. CSS 变量建议

建议在全局样式中集中声明语义变量，业务样式只引用变量，不直接散布十六进制颜色：

```css
:root {
  --canvas: #f4f5f1;
  --canvas-grid: #dfe4df;
  --surface: #ffffff;
  --ink: #17201d;
  --muted: #68736e;
  --line: #d8ddd9;

  --node-input: #29332f;
  --node-router: #a65f00;
  --node-llm: #4658a8;
  --node-message: #bb405b;
  --node-content: #16768a;
  --node-list: #7651a1;
  --node-tool: #1b774f;

  --type-control: #16845b;
  --type-content: #2f6fbb;
  --type-message: #d05a24;
  --type-list-content: #d12f72;
  --type-list-message: #7251b5;

  --interaction: #17201d;
  --status-success: #18734c;
  --status-warning: #b77900;
  --status-error: #b83a35;
  --disabled: #98a19c;
}
```

变量以语义命名，不以视觉名称命名。禁止新增 `--purple-2`、`--bright-blue` 等无法说明用途的变量。

## 7. 可访问性要求

配色实现必须满足以下要求：

- 普通文字与背景的对比度至少达到 WCAG AA 的 `4.5:1`。
- 大字号文字和非文本图形的对比度至少达到 `3:1`。
- 白色节点符号文字与职责色背景应达到可读对比度；不满足时应改用深色前景或加深背景。
- 任意两个连接类型不能只依赖颜色区分，必须同时具有不同线型或明确标签。
- 选中、错误、禁用和兼容状态必须至少再提供轮廓、图标、文字、透明度或尺寸变化中的一种提示。
- 不得通过降低文字透明度制造禁用效果，以免与背景混合后失去可读性；应使用明确的禁用色并保留足够对比度。

发布前至少检查普通显示、灰度显示和一种常见红绿色觉差异模拟。新增数据类型时，必须同时验证其与现有五种连接在颜色和线型上的区分度。

## 8. 实现映射

当前实现应按以下位置应用变量：

| 实现位置 | 使用的颜色层次 |
| --- | --- |
| `webui_py/static/css/base.css` | 定义全部语义变量 |
| `webui_py/static/css/workflow/layout.css` | 节点库标记、节点符号、工具栏状态 |
| `webui_py/static/css/workflow/canvas.css` | 节点顶部色条、端口、连接线、图例和交互状态 |
| `webui_py/static/css/workflow/inspector.css` | 端口合同和检查器状态 |

实现时先替换变量定义，再逐步消除 Workflow 样式中的硬编码业务颜色。中性色的局部微调可以保留，但任何用于表达节点类型、数据类型或状态的颜色都必须引用本规范中的语义变量。

## 9. 扩展规则

新增节点类型时，优先归入已有职责类别。只有当新节点承担无法归类的新职责，且需要在画布上被快速识别时，才新增节点职责色。

新增数据类型的门槛更高。新增前必须明确：

- 现有数据类型无法表达其连接兼容性。
- 新类型拥有稳定的数据契约，而不是单个节点的临时输出格式。
- 能提供与现有类型明显不同的颜色和线型组合。
- 前端端口、连接校验、后端解析器和文档能够同步支持该类型。

配色数量本身不是限制。真正的限制是每种颜色必须拥有单一、稳定且可解释的语义。
