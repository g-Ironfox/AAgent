# 03 模块详解

## 模块速查

| 要修改的能力 | 入口 |
|--------------|------|
| QQ 事件接收 | `qqbot/listener.py` |
| 事件分发、命令与回复 | `agent/task_worker.py` |
| LLM 上下文与调用 | `agent/llm.py` |
| 工具定义与执行 | `agent/tool.py` |
| QQ 消息发送(命令回复) | `agent/qqapi.py` |
| Redis 队列 | `agent/queue_client.py`、`qqbot/queue_client.py` |
| MongoDB 历史 | `agent/history_repository.py` |
| 监控 API 与页面 | `webui_py/main.py`、`webui_py/static/` |

> 修改 `task_worker.py`、`llm.py` 或队列操作前,先阅读[事件与队列](02-事件与队列.md)中的执行不变量。

## 1. qqbot 服务(`listener.py`)

- 用 `websockets` 连接 `QQ_WS_URI`,请求头携带 `Authorization: Bearer {QQ_WS_TOKEN}`;
- 循环接收 WebSocket 消息并解析 JSON;
- 对包含 `user_id` 的事件封装为 `qq` 事件,通过 `publish_to_queue()` 写入队列。
- `asyncio` 只用于入口网络 I/O,不会异步调用 LLM,也不会直接修改权威上下文。

```json
{
  "event_type": "qq",
  "payload": {
    "user_id": "...",
    "group_id": "...",
    "raw_message": "...",
    "message": "..."
  }
}
```

## 2. agent 主循环(`task_worker.py`)

- `main()` 是唯一状态推进循环:`BRPOP` 阻塞消费,同步执行完 `handle_task()` 后才获取下一个事件;
- 不得启动第二个 agent worker 消费同一队列,也不得将 `active` 分支改成线程、协程或后台任务;
- `handle_task()`:所有事件**先 `record_history()` 入库**,再按 `event_type` 分发:
  - `qq` → `user_interface()` 解析消息;
  - `terminal` → 记录历史后 `publish` 一个空 `active` 事件触发 LLM(消息内容已在历史中,`active` 不再携带);
  - `tool` → `execute_tool()` 执行,结果封装为 `tool_return` 事件 `insert` 插队(失败时 `success=False` 并携带错误信息);
  - `tool_return` → 仅记录;
  - `active` → `chat_with_deepseek()` 后生成 `response` 事件(有 `tool_calls` 时额外预插空 `active`);
  - `response` → 有 `tool_calls` 时逐个生成 `tool` 事件 `insert` 插队。

## 3. 用户消息处理(`user_interface`)

- 读取 `raw_message`、`group_id`、`user_id`;
- 消息以 `/` 开头按命令处理,结果回发(群消息回群、私聊回私聊):

| 命令 | 行为 |
|------|------|
| `/dsB` | 查询 DeepSeek 余额 |
| `/kmB` | 查询 Kimi 余额 |
| `/B` | 在一次命令中依次查询 Kimi 与 DeepSeek 余额 |
| `/search <关键词>` | Tavily 搜索,返回第一条结果的标题 |

- 非命令消息:若 `user_id == QQ_TARGET_USER_ID` 且(私聊,或群里被 `@` 即消息含 `[CQ:at,qq={BOT_ID}]`),则 `publish` 一个 `active` 事件触发 LLM 回复。

## 4. LLM 对话(`llm.py`)

- `chat_with_deepseek(messages)` 接收 active 分支组装好的消息数组;active 分支通过 `get_recent_history(limit=10)` 从 MongoDB 历史中 callback 所需信息;
- 将 `qq`、`terminal`、`response`、`tool_return` 投影为 LLM 消息;具体协议与截断取舍见[格式规范](06-格式规范.md);
- 使用 `requests.post()` 同步阻塞调用 DeepSeek `POST /chat/completions`;调用返回前 worker 不会处理其他事件;
- 返回 `(content, reasoning, tool_calls)` 三元组,由调用方(`handle_task` 的 active 分支)负责生成 `response` 事件和预插后续 `active`;
- `tool` 事件的生成由 worker 的 response 分支负责。

当前 callback 为过渡方案(固定最近 10 条),未来将演进为按相关性召回的 document callback。详见 [07-事件双重身份与信息回调](07-事件双重身份与信息回调.md) 和 [05-路线图与创新](05-路线图与创新.md#21-全局信息的-document-callback)。

## 5. 工具模块(`tool.py`)

注册到 DeepSeek `tools` 参数的工具:

| 工具名 | 功能 | 来源 API |
|--------|------|----------|
| `get_deepseek_balance` | 查询 DeepSeek 账户余额 | `DEEPSEEK_BASE_URL/v1/user/balance` |
| `get_kimi_balance` | 查询 Kimi 账户余额 | `KIMI_BASE_URL/v1/users/me/balance` |
| `tavily_search` | 网络搜索 | `https://api.tavily.com/search` |

其他说明:

- `bocha_search`:独立函数,**未注册**到工具链;
- Tavily 支持多 Key 轮询:`TAVILY_API_KEYS` 逗号分隔,请求失败自动切换;
- `execute_tool(id, tool, args)`:分发执行,结果转字符串,未知工具返回 `未知工具: {tool}`。

## 6. QQ API 封装(`qqapi.py`)

基于 `QQ_API_BASE_URL` + `Bearer {QQ_API_TOKEN}`:

- `send_group_msg(group_id, message)` / `send_private_msg(user_id, message)` / `send_private_img(user_id, img_bs64)`;
- `get_group_list()` / `get_group_member_info(group_id, user_id)` / `get_group_msg_history(group_id, message_seq, count)`。

## 7. 历史仓库(`history_repository.py`)

- `record_history(e)`:所有事件共用的记录入口,插入单条事件并附加 `created_at`(UTC);`response` 和 `tool_return` 通过新增事件直接复用这条管线,同时服务历史审计、LLM 上下文、WebUI 监控和工具追踪;
- `active` 与 `tool` 事件会记录但不直接投影为 LLM 消息;事件到消息的规则由 `task_worker.py` 的 active 分支负责,详见[格式规范](06-格式规范.md);
- `get_recent_history(limit=10, event_type=None)`:按 `created_at` 倒序查询最近 N 条;
- 启动时自动创建索引(详见 01 文档第 5 节)。
- 规划方向:从固定最近 N 条历史演进为全局 document 存储与按需 callback,详见[路线图与创新](05-路线图与创新.md#21-全局信息的-document-callback)。

## 8. WebUI 服务(`webui_py/main.py`,FastAPI)

- 事件流监控:`GET /api/events`（按“进行中 → Redis 消费顺序 → MongoDB 最近历史”合并事件,并返回各状态统计与数据源告警）；
- 事件入口:`POST /api/terminal` 接收用户消息,封装为 `terminal` 事件 `RPUSH` 入队(消息内容写入事件 payload,LLM 从历史中 callback)；
- 终端历史:`GET /api/terminal/history`(仅 MongoDB 已消费的 `terminal` / `response`,按 `_id` 倒序取窗口,前端追加去重)；
- 静态页面在 `static/`(由 FastAPI `StaticFiles` 挂载,`uvicorn main:app` 启动),端口默认 `8081`。
