# 03 模块详解

## 1. qqbot 服务(`listener.py`)

- 用 `websockets` 连接 `QQ_WS_URI`,请求头携带 `Authorization: Bearer {QQ_WS_TOKEN}`;
- 循环接收 WebSocket 消息并解析 JSON;
- 对包含 `user_id` 的事件封装为 `qq` 事件,通过 `publish_to_queue()` 写入队列。

```json
{
  "event_type": "qq",
  "payload": {
    "user_id": "...",
    "group_id": "...",
    "raw_message": "...",
    "message": "..."
  }
}
```

## 2. agent 主循环(`task_worker.py`)

- `main()`:`BRPOP` 阻塞消费,更新 `set_worker_status`,调用 `handle_task()` 分发,异常捕获后休眠重试;
- `handle_task()`:所有事件**先 `record_history()` 入库**,再按 `event_type` 分发:
  - `qq` → `user_interface()` 解析消息;
  - `tool` → `execute_tool()` 执行,结果封装为 `tool_return` 事件 `insert` 插队(失败时 `success=False` 并携带错误信息);
  - `tool_return` → 仅记录;
  - `active` → `chat_with_deepseek()` 后发送群/私聊消息;
  - `response` → 有 `tool_calls` 时逐个生成 `tool` 事件 `insert` 插队(不再生成 `active`,再次调用 LLM 由 `llm.py` 负责)。

## 3. 用户消息处理(`user_interface`)

- 读取 `raw_message`、`group_id`、`user_id`;
- 消息以 `/` 开头按命令处理,结果回发(群消息回群、私聊回私聊):

| 命令 | 行为 |
|------|------|
| `/dsB` | 查询 DeepSeek 余额 |
| `/kmB` | 查询 Kimi 余额 |
| `/B` | 同时查询 Kimi 与 DeepSeek 余额 |
| `/search <关键词>` | Tavily 搜索,返回第一条结果的标题 |

- 非命令消息:若 `user_id == QQ_TARGET_USER_ID` 且(私聊,或群里被 `@` 即消息含 `[CQ:at,qq={BOT_ID}]`),则 `publish` 一个 `active` 事件触发 LLM 回复。

## 4. LLM 对话(`llm.py`)

- 读取最近 10 条历史(全局,未按会话隔离),拼 `system` 消息"你是一个办公助手";
- 历史转换为 OpenAI 兼容格式:`qq` → `user`、`tool_return` → `tool`、`response` → `assistant`(含 `tool_calls` 时一并携带);
- 调用 DeepSeek `POST /chat/completions`(携带 `tools` 工具定义);
- 插入 `response` 事件(`insert` 插队);**有 `tool_calls` 时,先额外插入一个携带 `user_id` / `group_id` 的 `active` 事件**(RPUSH 顺序为 `[active, response]`,`response` 先被弹出,`active` 在工具链完成后被弹出,再次触发 LLM);
- `tool` 事件的生成由 worker 的 response 分支负责(见 02 文档)。

## 5. 工具模块(`tool.py`)

注册到 DeepSeek `tools` 参数的工具:

| 工具名 | 功能 | 来源 API |
|--------|------|----------|
| `get_deepseek_balance` | 查询 DeepSeek 账户余额 | `DEEPSEEK_BASE_URL/v1/user/balance` |
| `get_kimi_balance` | 查询 Kimi 账户余额 | `KIMI_BASE_URL/v1/users/me/balance` |
| `tavily_search` | 网络搜索 | `https://api.tavily.com/search` |

其他说明:

- `bocha_search`:独立函数,**未注册**到工具链;
- Tavily 支持多 Key 轮询:`TAVILY_API_KEYS` 逗号分隔,请求失败自动切换;
- `execute_tool(id, tool, args)`:分发执行,结果转字符串,未知工具返回 `未知工具: {tool}`。

## 6. QQ API 封装(`qqapi.py`)

基于 `QQ_API_BASE_URL` + `Bearer {QQ_API_TOKEN}`:

- `send_group_msg(group_id, message)` / `send_private_msg(user_id, message)` / `send_private_img(user_id, img_bs64)`;
- `get_group_list()` / `get_group_member_info(group_id, user_id)` / `get_group_msg_history(group_id, message_seq, count)`。

## 7. 历史仓库(`history_repository.py`)

- `record_history(e)`:插入单条事件,附加 `created_at`(UTC);
- `get_recent_history(limit=10, event_type=None)`:按 `created_at` 倒序查询最近 N 条;
- 启动时自动创建索引(详见 01 文档第 5 节)。

## 8. webui 监控面板(`main.go`)

- API:`GET /api/health`、`GET /api/queue`(队列快照,offset 从队尾起算)、`GET /api/status`(worker 状态)、`GET /api/history`(历史事件);
- 静态页面在 `static/`(嵌入二进制),端口默认 `8080`。
