# 05 已知问题与优化建议

> 更新日期:2026-07-31。基于当前代码仓库状态梳理。

## 优先处理

| 优先级 | 问题 | 影响 | 建议行动 |
|--------|------|------|----------|
| P0 | 测试脚本含硬编码 API Key | 密钥泄露、账号滥用 | 立即吊销旧密钥;删除 `agent/script.py`、`agent/2.py`、`agent/3.py` 中的密钥并改用环境变量 |
| P1 | 缺少 worker 所有权保护 | 误启动第二个 worker 会造成上下文分叉 | 增加 Redis 锁、租约或上下文版本校验 |
| P1 | 事件无幂等与去重 | 重复投递可能导致重复回复或重复工具执行 | 为事件增加唯一 ID 和处理状态 |
| P1 | 外部请求异常处理粗糙 | 网络抖动时任务直接失败 | 统一超时、错误分类和有限重试策略 |

> 单 worker 是设计约束,不是性能缺陷;问题在于当前只靠部署纪律保证它。

## 后续改进

| 类别 | 现状 | 建议 |
|------|------|------|
| 长期记忆 | LLM 仅读取最近 10 条事件 | 实现 Document Callback,按相关性召回全局信息 |
| 专门能力 | Skill-Tool 尚未实现 | 定义主 Agent 与专门 LLM 的结构化接口 |
| 搜索命令 | `/search` 只返回第一条标题 | 返回摘要、链接并支持结果数量 |
| 博查搜索 | `bocha_search` 已定义但未注册 | 确认保留后注册为工具,否则移除无效配置 |
| 可运维性 | 缺少完整健康检查与日志轮转 | 增加服务级健康检查、日志保留策略和告警 |

## 部署风险

- MongoDB 当前使用 root 账号,应创建最小权限应用用户;
- Redis 当前无密码,公网部署必须启用认证并限制网络访问;
- `.env`、运行数据和曾泄露的密钥不得进入版本库。

具体设计约束见[设计哲学](00-设计哲学.md),规划状态与完整待办见[路线图与创新](06-路线图与创新.md)。
