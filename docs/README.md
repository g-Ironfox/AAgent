# AAgent 核心设计

AAgent 是一个拥有全局认知和连续时间线的单一决策中心。当前系统只有一个权威上下文，LLM 与工具链严格线性执行。

## 文档结构

```
docs/
├── 00-设计哲学.md        ← 核心原则与不变量
├── 01-系统架构.md        ← 服务拓扑、数据流、一致性边界
├── 02-事件与队列.md      ← 事件类型、状态机、双端队列机制
├── 03-模块详解.md        ← 每个源文件的职责与关键逻辑
├── 04-配置与部署.md      ← 环境变量、Docker Compose 启动
├── 05-路线图与创新.md    ← 已实现 / 规划中 / 已废弃的能力
├── 06-工具消息格式.md    ← 工具结果如何进入 LLM 上下文
├── 07-事件双重身份与信息回调.md ← 事件既是触发器也是信息载体,两层如何解耦
├── 08-终端设计.md        ← 最高权限终端的事件语义、插队调度与全局历史投影
├── webUI/                ← WebUI 设计、优化记录
├── 审查日志/             ← 审查报告、问题清单
└── README.md
```

## 核心阅读顺序

| 你的目标 | 阅读路径 |
|----------|----------|
| 理解核心设计 | 00 → 01 → 02 → 07 |
| 修改业务代码 | 03 → 对应源码；工具上下文协议另见 06 |
| 启动和维护项目 | 根目录 README → 04 |
| 了解 WebUI | [08-终端设计](08-终端设计.md) → [webUI/前端优化记录](webUI/前端优化记录.md) → [webUI/前端事件流设计](webUI/前端事件流设计.md) |
| 安排未来开发 | 05 |

## 内容边界

- **核心文档**（00-06）定义当前 Agent 的设计原则、事件语义、模块职责、部署约束和演进方向；
- **[审查日志](审查日志/README.md)** 记录审查时间点、发现的问题、修复状态和优化过程；这些是特定时刻的快照，不随代码演进实时更新。

发生冲突时，以源码和本目录核心文档为准；审查日志不能作为当前行为依据。
