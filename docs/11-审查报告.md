## 一、业务逻辑问题(按严重度)

- [ ] **B1(高) `/` 命令无鉴权** — `agent/task_worker.py::user_interface`
  - `/dsB` `/kmB` `/B` `/search` 对群里**任何人**开放:余额信息泄露给全群,`/search` 消耗 Tavily 付费配额。
  - 建议:命令分支同样校验 `str(user_id) == TARGET_USER_ID`,或单独配置命令白名单。

- [ ] **B2(中-高) `assistant` 消息 content 可能为 `None`** — `agent/llm.py::chat_with_deepseek`
  - 有 `tool_calls` 时 `message['content']` 若为 `null`,会以 `content: null` 写历史、进上下文,DeepSeek 可能返回 400(09 文档 §5 写的是"空字符串",实际可能为 null)。
  - 建议:写 response 前 `content = message.get('content') or ""`。

- [ ] **B3(中) C2 未实施:历史仍按 `created_at` 排序** — `agent/history_repository.py::get_recent_history`
  - 08 报告阶段一已定方案(改 `_id` 倒序),当前代码未落地。同毫秒批量插入时顺序不稳,可能造成 LLM 上下文顺序错乱。
  - 修复:`.sort("_id", DESCENDING)`(`{"_id": 0}` 投影不影响排序)。

- [ ] **B4(中) C3 未实施:`json.loads(arguments)` 无容错** — `agent/task_worker.py` response 分支
  - LLM 返回非法 JSON 时异常被 `main()` 吞掉,工具链静默断裂,历史留下悬空 `response(tool_calls)`。
  - 修复:解析失败时生成 `success=False` 的 `tool_return` 并携带错误信息写回上下文。

- [ ] **B5(中) 启动竞态丢事件** — `docker-compose.yml`
  - agent 依赖 mongodb 用 `service_started`(Mongo 无 healthcheck),Mongo 未就绪时 `record_history` 抛错,事件已出队 → 永久丢失。
  - 修复:mongodb 加 healthcheck(`mongosh` ping),agent/webui 改 `condition: service_healthy`。

- [ ] **B6(中) 失败不重试,消息丢失(R1)** — `agent/task_worker.py`、`agent/llm.py`
  - 事件先出队再处理,LLM 调用失败/QQ 发送失败后不会重试。
  - 建议(与 D5 事件 ID 配套):`main()` 捕获业务异常后按类型有限重试(如 3 次),发送失败单独 try/except。

- [ ] **B7(低) `qqbot/queue_client.py` 的 `pop_from_queue` 用 `blpop`** — `qqbot/queue_client.py`
  - agent 版用 `brpop`(队尾弹),qqbot 版是 `blpop`(队头弹),方向相反。虽未使用,但一旦误调用会破坏队列语义。
  - 建议:删除未使用函数(08 报告 S5),或统一为 `brpop` 并补 `REDIS_SOCKET_TIMEOUT`/`decode_responses`。

- [ ] **B8(低) `send_messages` 每轮 `print(resp.json())`** — `agent/llm.py`
  - 打印完整 API 响应,日志噪音大。
  - 建议:改为只打印 `message['content']` 长度或省略响应体。

- [ ] **B9(低) `qqbot` 每条消息开一个线程** — `qqbot/listener.py`
  - `asyncio.to_thread(publish_to_queue, ...)` 每次新建线程;redis-py 客户端也每次新建连接。
  - 建议:模块级单例连接(参考 08 报告 R4)。

- [ ] **B10(低) 未知事件类型静默忽略(D2)** — `agent/task_worker.py::handle_task`
  - 建议:改为 dict 分发表,未知类型打印告警(08 报告 D2 方案)。

- [ ] **B11(低) 余额查询无网络异常捕获(R3)** — `agent/tool.py::deepseekBalance/kimiBalance`
  - 网络异常/响应结构变化时抛 `KeyError`/`ConnectionError`,使工具链断裂。
  - 建议:try/except 返回 `None`,`bocha_search` 补 return 与超时或删除。

## 二、前端 / UI 问题

- [ ] **F1 07 文档 §4.3"内容签名跳过重渲染"在代码中缺失** — `webui/static/render.js`
  - `renderTimeline` 无 signature 脏检查,每 2s 轮询对全部行重写 `textContent`。DOM 复用与 `.enter` 动画已实现(无闪烁),但文档描述的优化与代码不一致。
  - 建议:补内容签名短路,或同步修正 07 文档。

- [ ] **F2 无 favicon** — `webui/static/`
  - 控制台 `GET /favicon.ico` 404。可加内联 `<link rel="icon">` 或用 data URI。

- [ ] **F3 搜索无 debounce** — `webui/static/app.js`
  - 每次按键全量 `JSON.stringify` 150 行。建议加 150ms 防抖。

- [ ] **F4 done 行 ID 含 `created_at`,同毫秒重复事件 ID 冲突**(极低概率)— `webui/events.go`
  - `ID: "done-" + fingerprint + "-" + fmt.Sprint(createdAt)`,同毫秒两条完全相同内容的事件会得到相同 ID。
