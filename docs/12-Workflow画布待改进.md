# Workflow 画布待改进

本文记录当前 Workflow 前端画布方案中已经识别出的设计问题、待改进项和建议实现顺序。本文是实现规划，不改变当前 Workflow 的业务数据契约。

## 1. 当前方案的问题

当前画布通过较大的固定工作区和隐藏原生滚动条实现平移：

- 工作区默认尺寸为 `1800px × 1200px`。
- 通过 `scrollLeft` 和 `scrollTop` 保存当前视口偏移。
- 在画布空白区域拖拽时平移视口。
- 节点拖拽和端口拖拽拥有更高的交互优先级。

这个方案可以满足初步使用，但存在以下长期问题：

- 视口状态分散在 DOM 滚动属性中，后续加入缩放时坐标换算容易不一致。
- 固定工作区边界限制了节点继续向右下方扩展。
- 左上方向没有真正的负坐标模型，画布原点和可移动范围不够自然。
- 连线拖拽到视口边缘时无法自动查看画布外的节点。
- 目前还没有统一的缩放、聚焦节点和适配全部节点能力。

## 2. 优先级划分

### P0：统一视口与坐标模型

视口必须成为独立的编辑器状态，不属于 Workflow 业务状态：

```js
const viewport = {
  x: 0,
  y: 0,
  zoom: 1,
}
```

应集中提供以下坐标转换能力：

```js
screenToCanvas(screenPoint, viewport)
canvasToScreen(canvasPoint, viewport)
```

节点移动、端口命中、连线预览、框选、自动平移和节点定位都必须使用统一的坐标转换，不应在不同模块中分别拼接 `scrollLeft`、`scrollTop` 或缩放比例。

第一阶段可以继续使用 DOM 滚动属性作为底层实现，但上层代码必须通过视口控制器访问，不能让业务模块直接读取或修改滚动属性。

### P0：明确画布手势优先级

不同起始位置必须有稳定且互不冲突的交互规则：

| 起始位置 | 默认左键拖动行为 |
| --- | --- |
| 输入或输出端口 | 创建或编辑连接 |
| 节点主体 | 移动节点 |
| 画布空白区域 | 平移视口 |
| 画布空白区域 + `Shift` | 框选节点，待实现 |
| 任意画布区域 + `Space` | 平移视口，待实现 |
| 鼠标中键 | 平移视口，待实现 |

交互命中顺序应为：端口优先于节点，节点优先于画布，画布优先于画布上的浮动工具。图例、小地图、缩放工具条等非画布 UI 不能被识别为空白画布。

所有平移和拖拽操作都必须支持 `pointercancel`，页面失去焦点或指针离开窗口时也应正确清理临时状态。

### P1：动态工作区边界

固定 `1800px × 1200px` 只作为过渡方案。长期方案应允许工作区根据节点和视口动态扩展：

- 节点接近右侧或下侧边界时，自动扩展工作区。
- 节点接近左侧或上侧边界时，扩展工作区并同步调整视口原点，避免节点被强制限制在正坐标区域。
- 节点四周保留足够安全边距，建议至少 `320px`。
- 扩展工作区不应被视为 Workflow 业务修改。
- 不能通过无限增大 DOM 尺寸造成不必要的重绘和内存开销。

节点的业务位置仍应属于节点布局数据，视口偏移只属于编辑器状态，二者必须分开处理。

### P1：连线拖拽时的边缘自动平移

用户从端口拖拽连接并靠近视口边缘时，画布应自动平移，以便连接到当前视口外的节点。

要求：

- 只在连接拖拽状态中启用。
- 鼠标进入边缘触发区域后开始平移。
- 距离边缘越近，平移速度越快。
- 水平和垂直方向可以同时自动平移。
- 鼠标离开边缘区域、连接完成或拖拽取消时立即停止。
- 自动平移过程中持续刷新连接预览。
- 预览终点必须通过统一坐标转换计算，不能直接使用屏幕坐标。

建议边缘触发区域为视口边缘 `32px` 到 `48px`，速度设置最大值，避免一次移动过远导致用户失去目标节点。

### P1：缩放与视口定位

大画布需要提供基础的缩放和定位能力：

- `Ctrl` 或 `Cmd` + 滚轮：以鼠标所在位置为锚点缩放。
- 普通滚轮和触控板滚动：平移视口。
- 缩放范围建议为 `0.5` 到 `2`，默认值为 `1`。
- 工具栏提供放大、缩小、重置缩放按钮。
- 提供“适配全部节点”操作。
- 提供“聚焦选中节点”操作。
- 适配和聚焦只改变视口，不改变节点坐标，不触发未保存状态。

缩放时必须保持鼠标下的画布坐标不变，避免画面围绕左上角跳动。缩放按钮需要使用图标，并提供可访问名称和悬浮提示。

## 3. 保存与编辑器状态

Workflow 状态应明确分成业务状态、布局状态和视口状态。

### 3.1 业务状态

业务状态参与未保存判断：

- 节点新增和删除。
- 节点配置变化，例如名称、提示词、模型、工具和分支。
- 连接创建、删除、替换和改接。
- Workflow 重置。

### 3.2 布局状态

布局状态包含节点的 `x`、`y` 坐标：

- 单纯拖动节点不触发未保存提示。
- 用户点击保存时，节点坐标和业务状态一起写入草稿。
- 节点坐标应继续保存，以便下次打开时恢复布局。
- 未来可以提供单独的布局保存或自动保存策略，但不能让布局拖动频繁触发离开确认。

### 3.3 视口状态

视口状态包含：

- 平移位置。
- 缩放比例。
- 当前选中节点。

视口状态不参与未保存判断。建议将其作为浏览器本地编辑偏好单独保存，以便用户再次打开 Workflow 时恢复上次浏览位置；视口状态不应写入 Workflow 的业务版本或同步协议。

### 3.4 动态端口配置不能清除控制流

节点切换 Tool 或修改数据类型、数据输入数量时，端口集合可能发生变化。连接清理必须只针对失效的数据端口，不能因为节点重新渲染或数据端口变化而删除控制流连接。

已确认的历史问题：

- `tool` 切换 Tool 时曾无条件删除所有入站连接，导致连接到 `control-in` 的控制流被清除。
- `construct_list` 切换元素类型时曾删除该节点所有入站和出站连接，导致 `control-in` 和 `control-out` 控制流被清除。

修复规则：

- 切换 `tool` 时保留所有 `control` 连接，只删除目标参数已不存在的 content 连接，并保留仍然有效的参数连接。
- 切换 `construct_list.item_type` 时保留所有 `control` 连接，只清理与旧数据类型或旧数据端口不兼容的数据连接。
- `foreach` 切换元素类型时必须保留 `control-in`、`loop-in`、`control-out` 和 `loop-out` 相关控制流。
- 删除分支、删除动态输入或关闭可选输出时，只删除被删除端口对应的连接。

实现时不要使用“删除节点全部入边/出边”作为动态配置变更的通用处理。连接清理条件必须同时检查连接类型和端口 ID；控制流通过 `connection.type === 'control'` 保留，数据流则根据变更后的端口契约进行校验。

回归检查至少覆盖：切换 Tool 后上游控制流和下游控制流仍存在；切换 `construct_list` 元素类型后控制流仍存在且旧数据连接被清理；`foreach` 切换元素类型后两条控制入口和两个控制出口不受影响。

## 4. 交互状态清理

需要统一管理以下临时状态：

- 当前平移是否进行中。
- 当前节点是否拖动中。
- 当前连接是否拖动中。
- 当前是否处于空格键平移模式。
- 当前是否处于边缘自动平移。
- 当前指针是否仍被捕获。

任何结束路径都必须清理状态：

- 正常 `pointerup`。
- `pointercancel`。
- `window.blur`。
- 连接拖拽落点不兼容。
- 节点或端口被重新渲染。
- 用户按下 `Escape`。

清理时不能误创建连接、误移动节点或残留 `grabbing`、兼容端口高亮和自动平移动画。

## 5. 后续增强

这些功能不属于第一阶段，但应避免与基础坐标模型冲突：

- `Shift` 框选多个节点。
- 多选节点整体移动。
- 网格吸附和对齐辅助线。
- 自动布局。
- 节点数量较多时显示小地图。
- 键盘方向键移动选中节点。
- `Delete` 删除选中节点。
- `Escape` 取消连接拖拽、框选或平移模式。
- 新建节点或选中节点后自动将其移动到可见区域。

## 6. 推荐实现顺序

1. 建立独立的视口状态和坐标转换函数。
2. 统一端口、节点、画布和浮动 UI 的手势优先级。
3. 把固定工作区改为动态扩展工作区。
4. 增加连接拖拽期间的边缘自动平移。
5. 增加以鼠标为锚点的缩放和基础定位按钮。
6. 增加视口偏好的本地持久化。
7. 在基础坐标模型稳定后，再实现框选、多选、小地图和自动布局。

每项实现都应至少验证以下行为：

- 平移不会改变节点坐标。
- 平移不会触发未保存提示。
- 节点拖动不会触发画布平移。
- 端口拖动不会触发节点移动或画布平移。
- 平移和缩放后连线仍准确连接端口。
- 刷新后业务状态、节点布局和视口偏好符合各自的保存规则。
